# 开发验证规范

按改动风险选择最低充分检查，覆盖实际入口、处理、结果和适用失败边界。命令均在仓库根目录执行，先满足 [README 工具链前提](../../README.md#离线-ios-app-开发入口)。页面开发前读取本文页面复测部分和 [DESIGN 响应式契约](../../DESIGN.md#8-responsive-behavior)。

本分支仅保留离线 iOS CI：PR 自动按变更运行常规检查；模拟器专项在本地按变更验证，完整候选及容量在最终候选阶段本地集中验收；没有 PR 的普通分支 push 不运行远端验证。旧 Web/服务端的 release-gate（含 PostgreSQL、Java、浏览器及服务器部署检查）已撤下，不再安装 PostgreSQL 16。仓库通用 secret 检查拆出为 scripts/check-secrets.sh，由离线流水线保留，不依赖 Java 或旧端依赖。退役入口不再提供手工运行；历史命令及要求从文档索引中的固定基线查看。

## 工程检查

| 命令（根目录） | 何时使用 | 做什么 |
|---|---|---|
| npm run check:app | 离线 App 入口、依赖或资源变更 | Node 24：领域、队列、初始化状态、字典/合并 SQL、组件四态及设计契约测试、类型检查、Vite 构建、Capacitor sync、生成 SPM 兼容适配及资源门禁正反例；不启动 Web/PG |
| npm run build:ios-app | 原生工程/依赖或安装候选资源变更 | Xcode 27 / iOS 27 SDK：未签名真机架构 Release 编译与产物资源检查；不证明签名/可安装 |
| npm run check:ios-app:simulator | 原生 SQLite 桥、外壳及导航变更 | Xcode 27 / iOS 27.0 runtime：独立 iPhone 14 Pro Max 模拟器，hosted XCTest 验随包入口、原生事务/精度/聚合溢出拒绝、正式初始化/升级/seed 保护、八类字典和合并/模板事务、原页面操作、进程中断重开及排除系统备份；清理本轮设备 |
| npm run check:ios-app:touch | 影响跨场景原生交互、夹具隔离或完整触摸编排时；单页定位先选对应局部场景 | 独立 iPhone 14 Pro Max 模拟器；外部 XCUITest 对 Release App 依次验证字典与末页治理、收支保存/编辑/重启、草稿/偏好/模板、调整/回收站、明细筛选/搜索/分页、总览/五种时间粒度及九类支出/五类收入报表；各组准备专用合成夹具并只读回验 SQLite，包含隔离拒绝负例与设备清理；不替代真机交付 |
| npm run debug:ios-app -- list | 最低层检查、原生单用例或单场景定位 | 列出 check 白名单与可选用例/场景；create/run/suspend/close 显式管理本轮独立模拟器，按内容摘要复用构建，结果仅记局部验证 |


常规局部修改选择最低充分检查，不默认每次全跑；纯文档通常检查差异、引用与事实。检查以实际执行及退出状态判断，数据库测试被跳过不能记为通过。app/dist、原生随包资源和 Xcode 产物由脚本生成，不手工编辑。

App 检查统一从 [ios-app.sh](../../scripts/ios-app.sh) 进入 [命令调度器](../../scripts/ios-app.mjs)，完整检查委托 [完整流程](../../scripts/lib/ios-app-full.sh)，需先按 [README](../../README.md#离线-ios-app-开发入口) 安装 app 锁定依赖。各入口只证明本次回执中实际执行的范围；基础 sqliteProbe 使用受控实验数据，不能代替正式记账、完整升级/恢复、容量或真机验证。金额、时间及文本实现统一位于 app/src/domain；App 只消费本地契约与领域实现。模拟器入口通过 test bundle 调用正式 LedgerDatabase.open→upgrade，在保护快照完成、迁移 SQL/履历已写但事务未提交、升级事务已提交三个阶段分别挂起；脚本动态定位本轮沙盒，观察到匹配阶段信号后仅终止本 App。每次故障步骤须返回预期 65，恢复 XCTest 必须核对已提交基线、版本/结构/履历及重试结果，并回读保护快照排除标记。另外通过原生文件守卫用例验证完整头中 magic 清零的非热 journal 可保留（包括其余头字段仍有值的情况），热 journal、短头和非空 WAL 拒绝复制；正式中断重试用例必须能重新生成快照。原始 SQLite 事务探针不能代替这组正式流程验证；模拟器不验证实体文件保护等级。

App 设计门禁由 [designContract.spec.ts](../../app/src/app/designContract.spec.ts) 经 check:app 同一入口执行：Vue/TypeScript 解析真实导入和模板消费，核对九个核心组件登记、个人页面的唯一角色/路径及实际路由，拒绝私有颜色、注释假导入、缺登记与重复角色反例。21 个关键共享组件模板及三份全局样式的 SHA 基线来自准备提交 6419b93；已登记的搜索输入绑定及横屏键盘样式适配均须可逆还原并匹配原摘要，例外不豁免其他布局变化；未作为检查目标的业务消费者仍须按改动复核。四态及初始化重试由组件/状态测试覆盖，不用它们证明原生呈现。

[关闭重试回归](../../app/src/data/ledgerDatabase.spec.ts) 经 check:app 执行，在原生桥边界注入失败，覆盖关闭后禁止读写、保留所有权、重复关闭、直接重开及打开/校验与关闭同时失败的原因链；它不模拟真实 SQL 持久化。check:ios-app:simulator 的 lifecycleProbe 在真实原生库上补充注入关闭拒绝，恢复后调用真实关闭/重开，核对数据集、已提交金额和同名账本交接；故障包装仅存在于 test bundle，finally 恢复，不进入生产入口。

原生 [shellProbe](../../app/native-tests/shellProbe.ts) 在实际 WKWebView 中检查四导航、原图标、切页草稿、主题及抽屉焦点返回。嵌套放弃/取消使用 test bundle 内共享组件夹具，验证父子层与未保存作用域，不冒充账目编辑链路。探针不进入生产资源。主题选择接 SQLite 后，探针在每次点击前等待上一笔保存结束、控件恢复可用，不能把对禁用控件的 DOM 点击当作已执行。页面复测按[离线 App 设备选择](#离线-app-设备选择)覆盖受影响的导航、表单、完整软键盘、原生选择器、主题、方向及减少动态效果；小/默认/大 iPhone 的完整适配矩阵在首次适配、相关布局/响应式契约变化或最终集中复核时执行，纯数据或工具改动不机械重复全部设备矩阵；记录原页面操作和各自边界，不将脚本派发事件当成触摸验证。未接通功能应显示明确不可用而非假成功。

[字典场景](../../app/test-support/dictionaryScenarios.ts)与[升级场景](../../app/test-support/dictionaryUpgradeScenario.ts)由 Node SQLite 测试及原生 dictionaryProbe 共用，覆盖八类字典、规范化唯一键、两级分类、有界分页、排序故障回滚、类型/引用保护、历史快照、模板冲突（含相同时间下 UUID 有符号高/低位的取舍）、合并幂等及 v1→v2 升级。Node 测试只在原生桥边界换成临时文件 SQLite，不证明 iOS 文件策略，也不进入生产包；原生测试经正式生命周期核验相同 SQL/事务及快照。seed A/B 样本核对用户改名/停用/排序、删除项及 false/0/空值不被新版清单覆盖，并验证必需数据迁移冲突的拒绝、回滚与重试。

[字典详情组件回归](../../app/src/views/me/dictionaries/DictionaryDetailView.spec.ts)挂载正式页面，在 API 边界控制响应顺序，检查末页收敛、补读失败后的重试，以及旧补读晚于新搜索翻页返回时不覆盖新结果或页码；它不替代原生 SQLite 与触摸验证。

[dictionaryUiProbe](../../app/native-tests/dictionaryUiProbe.ts)驱动正式页面与原生 API，核验八类入口、新增/重名保留输入/改名/停用/恢复、预览取消不写入及确认合并。历史账目和模板仅在隔离测试沙盒经原生连接准备，合并后直接读回金额和快照；该字典探针不操作账目保存、明细或模板 UI，这些消费者按对应业务场景另验。派发事件证据还须配合模拟器图标启动后的实际触摸、键盘和页面核验。

NativeTests 与 DictionaryUITests 只支持 simulator SDK，并由共享 [OwnedSimulatorTestContext](../../app/ios/App/NativeTests/OwnedSimulatorTestContext.swift) 在注入探针或启动 UI 操作前核对本轮设备；物理设备测试编译直接拒绝。生产 App 不编译守卫、不读取清单。清单来源及传递见[环境架构](../architecture/environment-configuration.md#离线-app-原生测试配置)，不手工绕过 Xcode 直接测试的拒绝。原生守卫用例覆盖平台、缺失/不匹配设备、路径、App ID、大小及无效内容；touch 脚本另在本轮空模拟器对两个入口去掉清单，要求具体用例以隔离守卫错误失败、xcodebuild 返回 65，再只读确认业务行未增加。普通测试失败返回 65 不能充当该负例成功。

脚本先构建、安装并等待专用模拟器正式账本完成初始化，结束宿主后再执行测试，以分离首次运行时准备；准备有界等待不属于冷启动性能测量，也不改变原生入口 20 秒等待和普通单用例 60 秒预算。局部入口的启动、账本就绪和结束宿主分别保留 initialize-launch.log、initialize.log、stop-initialize.log；局部和完整入口的启动/终止输出直接写文件，初始化同时将 App 自身 stdout/stderr 写入本轮私有日志（局部 initialize-app-*、完整 prepare-app-*），以命令退出状态判断完成，避免辅助进程继承输出管道导致已退出命令仍等待 EOF。缺少就绪标记或终止失败仍拒绝准备夹具，整个初始化阶段继续受同一 60 秒预算约束。自动回归的 TestAction 不挂载调试器，日常 Run 调试设置保持；正式性能验收仍按目标真机 Release 规则执行。

[原生触摸用例](../../app/ios/App/UITests/DictionaryTouchTests.swift)由独立 DictionaryTouch scheme 执行，使用 XCUITest 的 tap/typeText/原生选择器操作 Release App，不注入 JavaScript、不替换业务 API。与 hosted XCTest 的 DOM 事件场景分别记录，不将两者混称为真实触摸。check:ios-app:touch 先验证正式初始化并结束宿主，再用[受限夹具](../../scripts/fixtures/dictionary-touch.py)准备本轮空模拟器账本的历史引用；夹具拒绝已有自定义数据，不清空、不连接真机。缺少归属清单的预期拒绝完成后，先重启同一受管模拟器以释放 UI runner 会话，再准备正例夹具；设备 UUID、账本和清单保留。原有 11 项 UI 用例顺序共用本轮交互会话，各用例保留截图，最后验证重启；回读后追加 21 项商品/单位夹具，以另 4 项用例验证搜索末页合并、启用筛选末页停用后的有效页回退及条件保留，再只读核验结果。脚本结束 App 后回读稳定 ID、引用、模板、行版本、金额、名称快照、事件和幂等回执，执行完整性及外键检查；用例按操作链路拆分并保留原 60 秒执行预算配置，不上调超时；改名等实际输入后以 3 秒有界等待核对 AX 精确值；局部键盘前置只建立空搜索输入会话，不重复输入或提交查询；搜索和表单共用原生收键盘辅助：已收起时无操作，显示时只选择当前可触摸的“完成”按钮并断言键盘消失；拒绝遗留同名 AX 节点，不以滚动替代收起；合并保留商品的“请选择”提示值不依赖 AX label，以截图定位后原生触摸；触摸定位仍可用本机 Vision OCR 定位截图文字，再由 XCUITest 坐标触摸；通用可见文字断言保留画面或 AX 命中的原判据，先观察画面，避免慢 AX 快照错过短暂提示。不将 OCR 通过作为无障碍验收。此流程只证明开发模拟器的页面链路，不代替目标真机性能和最终交付。

资源门禁使用锁定的 TypeScript 解析器检查 JS/MJS/CJS 及内联脚本，拒绝已知 IndexedDB、Web Storage、WebSQL、WASM 的直接标识符、别名来源与静态括号访问；合法注释及文案不作为调用。该静态检查不证明所有动态间接访问不可达，正式数据入口仍须通过原生集成验证。正反例通过同一门禁入口执行。

每轮 build.log/test.log、interruption-阶段/recovery-阶段 日志、阶段回执及 xcresult 位于 .local/ios/tmp/ai-agent/native-*；失败不冒充成功，模拟器清理失败也返回失败。原生缓存与产物留在 .local/ios，不复用 .local/web。旧 Web/Safari 自动化入口已退役；不能用浏览器结果代替原生测试。

设备选择、提前使用真机的条件及最终候选范围见[离线 App 设备选择](#离线-app-设备选择)。模拟器开发观测不能替代目标真机 Release 的约定容量采样、辅助功能及硬件复核；执行器或必要实测尚未完成时保留待验证。

### 原生局部调试与完整验收

日常开发、局部修复及阶段推进以本地最低充分验证为准：先执行目标文件或用例，只有风险确实跨越该层才扩大。下面的场景表决定本轮必需范围；必要局部检查失败仍须修复，不能将实际失败记为计费问题。远端计费、额度、排队或平台故障单独记为“远端受阻/未验证”，保留已完成的本地结论，不阻塞不依赖远端机制的开发、提交与推送，不触发自动重跑或扩大验收。涉及 GitHub 特有触发、权限或 runner 行为的结论须保留远端待验，最终交付前补齐。选择依据、命令和结论边界写在交付回复，不新增过程台账。

| 场景 | 首选方案与扩大条件 |
| --- | --- |
| 金额、日期、SQL、迁移、队列或业务状态 | 先选文件，例如 `npm run debug:ios-app -- check --check app-tests --file src/domain/money.spec.ts`，可追加已有 `--name` 过滤；仅原生桥或文件策略无法由 Node SQLite 证明时补对应 hosted XCTest，不因 SQL 文件变化默认运行触摸套件 |
| Vue 请求时序、搜索、草稿、错误与取消 | 对应真实组件或组合函数的 Vitest；纯事件调度未改呈现或原生机制时复用范围匹配的页面证据。键盘、选择器、滚动或实际触摸命中变化再选原生 UI 单例 |
| 验证脚本、缓存、安装与夹具隔离 | Node 脚本测试、受控 CLI 和真实 SQLite 文件故障注入。仅回执、失败目标、CI 策略或目录替换状态变化时，验证对应允许/拒绝和恢复路径；未改实际构建参数、安装方式、UI 驱动或原生桥，可沿用范围匹配的原生证据。实际包/资源或原生编排机制变化再用同一独立模拟器做冷准备与热复用小场景，不重复完整 touch |
| Swift 原生逻辑或 UI 定位器 | 协调器或桥接变化选对应 hosted XCTest；仅触摸定位器变化选相应 UI 单例及显式必要前置。利用分层缓存保留未变资源、App 安装和本轮设备 |
| 多步骤状态依赖或跨页面链路 | 单项稳定后运行对应 `--scenario` 小组合一次；失败立即缩回目标。只有局部不能证明影响范围或候选集中验收需要时才进入既有完整入口，并满足下表证据锁 |
| 首次安装、升级中断、签名、离线、容量与硬件 | 首次初始化和完整升级入口保留冷路径，不能以基线恢复冒充；中断使用成对场景。模拟器无法覆盖的签名、硬件及最终 Release 性能按既定真机条件验证，不把调试缓存耗时当作冷启动性能 |

本机默认并行导致 App 单测争用资源时，可在本次命令前设置 `VITEST_MAX_WORKERS=2`，与常规覆盖率检查的两 worker 设置一致；先复验超时文件，保持原断言和单例时限，不以停止其他项目服务为前置。该变量只影响 Vitest，不改变原生初始化、触摸或性能预算。

失败先依据 result.json 的 failure.stage、timings.json 和对应日志区分构建、安装、初始化、测试及回读。初始化卡住时先保留会话和制品，核对启动回执及正式账本提交；需要时有界采样本轮进程，随后只恢复同一 UUID、执行最小相关用例。不得仅因初始化超时执行 close/create、删除 DerivedData 或重跑完整构建；真正的包变化或产物损坏才使构建或安装失效，实际设备丢失或损坏须先有证据再另建。中途暂停用 suspend，全部定位与复验结束才 close。

CLI 预启动后的前台状态和 SQLite 初始化成功不能证明 WebContent 已绘制；共享键盘前置在画面尚未显示首页标题时，复用原生 WebView 激活，再通过既有 20 秒页面就绪检查；导航使用既有原生控件优先、截图回退的点按器，不以单独 OCR 漏识别判定页面失败，仍受原 60 秒单例预算约束。字典搜索先确认原生键盘就绪，输入后完成原生编辑，再沿用金额输入的精确值核对，不重放输入。iOS 搜索触摸同样先确认完整键盘并处理首次系统引导，竖屏先完成一次原生键盘窗口交接，再输入并结束预编辑核对提交值；横屏先回读同一搜索，明确将光标置尾后实际退格并核对清空；两种方向均核对键盘与保存可达性，保留原 3 秒精确值窗口，避免重复输入相同文本。 该单例对已存在的搜索框/键盘先检查 exists，缺失时仍按原 3 秒窗口等待；已知单价控件由相同标识查询直接做精确回读，不叠加不必要的存在轮询。 空值断言须先读到字符串，不把两个 nil 相等当成已清空。 iOS 候选/类型切换的回读同时核对 recentEntryType 和正式偏好保存产生的 updatedAt；时间须属于捕获至回读窗口且为有效毫秒 UTC 时间，缺失、非法、跨轮和其他偏好改写仍拒绝；只建立键盘的场景不允许新增偏好元数据。新建调整弹层的专用用例仅在受管 iPhone 14 Pro Max 竖屏使用已观测的系统栏勾选位置：空初值、键盘存在和方向均先校验，随后仍须通过键盘消失、精确金额及 SQLite 结果核对。字段值同步使用显式 AX 新查询与单调时钟，第一次立即读取，后续只消费原 3 秒窗口剩余时间；查询结束超过窗口的值不能判通过，失败诊断复用窗口内最后一次观测及查询耗时，不在超时后再次读取造成相同值误判。iOS 候选的集中复核使用既有 ios-interaction 三例顺序，保留同一测试会话的键盘导航前置；拆出的 ios-candidates 用于前置已确认后的局部定位，不能以重试替代缺失的输入窗口准备。系统 AX 读取本身卡住仍记失败，不以延长同步窗口解决。

先在能证明问题的最低层定位：纯领域、组件与执行器问题先用 Node/Vitest；桥接或页面触摸问题再运行对应原生单用例/场景。局部通过且相关源码稳定后，仅在影响范围确有必要时执行一次完整验收；共享脚本变化不自动要求重跑全部页面。以下规则由 [ios-verification.mjs](../../scripts/lib/ios-verification.mjs) 与根目录统一入口强制执行，适用于本机和 CI，不提供 force/skip/CI 环境变量绕过：

| 条件 | 实际执行约束 |
| --- | --- |
| 首次启动 simulator/touch 完整验收 | 必须提供 `--from RUN_DIRECTORY`，指向本工作区受管局部运行的当前版本成功回执（ios-check-* 或会话 run-*）；先校验回执、实际用例通过日志、范围、完成时间及输入摘要，再允许生成资源和启动完整工作 |
| 正例出现失败或执行时间告警 | 每 100ms 观察正例日志；发现首个失败立即终止本次进程组并执行清理，不继续后续测试阶段；记录失败用例及日志路径，下一步只能先局部定位 |
| 完整验收失败、取消或宿主中断 | 工作区状态保留失败/未完成锁；旧回执、失败之前的回执、无关用例以及改跑另一完整套件均拒绝。失败的用例、具体场景、Vitest 精确目标、资源目标或构建/安装阶段必须由新局部成功证据覆盖；首次完整验证及完整失败后的局部新故障也须有相关修复证据；当前输入的各套件结论从完整历史取得，不能以其他输入后来通过覆盖旧输入的失败；不将无用例名称的失败降级成任意原生烟测，缺入口先补入口 |
| 同一输入复验再次失败 | 每个输入和故障事件只允许初验加一次相关局部证据解锁的复验；A→B→A 保留 A 的历史次数。再次失败/中断后须修正相关输入并重新局部验证，不能靠换输入再切回或刷绿色重置次数 |
| 完整验收已通过且输入未变 | 默认拒绝再次启动。若通过后实际观察到同输入的新局部失败，须记录真实失败事件，并在其后取得覆盖全部相关目标的新成功回执，才开放该故障事件的复验；空匹配、取消、旧证据或无故重跑绿色不能解锁。README、规范措辞和生成物不使完整证据失效 |
| 分阶段超时 | 所有根目录入口（含 common / ios-build）的单次构建 10 分钟、显式安装 2 分钟、设备启动 2 分钟、初始化 1 分钟、非原生检查 5 分钟；build-for-testing、simctl install 和 test-without-building 分开计时并写 timings.json。测试启动/用例交接等待 180 秒；局部 UI 预启动与 runner 准备共用同一启动窗口，不重置起点，也不消耗已结束的账本初始化预算，普通单用例仍为 60 秒（容量 native/pages 的明确例外见下节）；预期中断准备为 120 秒。XCTest 可能再次校验或安装 runner，其耗时属于测试准备，不包含编译 |
| 整轮超预算 | 调度器从入口建立单调时钟截止时间，SDK、runtime、Xcode 查询、证据检查及后续构建/执行共用剩余预算，不在进入验收体时重新计时。debug 局部调试与 ios-smoke 为 15 分钟；覆盖字典、收支、个人状态、生命周期、明细、报表及数据管理的 ios-touch 独立为 40 分钟，common / ios-build 仍为 40 分钟。预算由 totalBudgetFor 同时供入口截止时间和完整子流程使用，不受命令参数或环境变量覆写。CI `checks` 矩阵中的原生组全部步骤共用外层 45 分钟，脚本/通用组为 10 分钟。其中每个构建/检查阶段仍分别受 10/5 分钟限制，单条工具链查询最多 5 分钟，实际取阶段/子命令上限与整轮剩余时间的较小值。超时终止后最多再给清理 10 秒；各阶段和单用例预算仍独立生效；完整触摸的总预算匹配多阶段范围，不把局部调试、单用例或初始化故障改成更长等待 |

输入摘要覆盖 App、测试/探针、Vitest 执行配置、工程、依赖锁、Node、宿主系统/架构，以及执行器、夹具和资源门禁；原生证据另绑定 Xcode、iOS SDK 与模拟器 runtime build，Node 检查不要求安装 Xcode。局部构建缓存与执行证据摘要分别维护，不因夹具修改无谓重编原生包。`.local/ios/tmp/ai-agent/ios-verification-state.json` 与 `ios-full-*/result.json` 保存尝试、来源证据、失败锁和次数；schema 2 保留全部历史及新局部失败事件，从 v1 合并已有逐轮回执并保留次数，不因关闭调试会话删除。禁止删除状态、换会话/工作目录或直接调用内部 Shell 规避限制，也不得用无关注释/格式改动刷摘要重置次数；内部 Shell 在生成资源前核对调度器活动许可。进程被 SIGKILL 留下 running 状态时按未完成处理，不自动放行。

UI 局部运行的设备恢复同时追溯最近的实际测试和未完成的 App 启动请求。`initialize-launch.log` 已创建但初始化失败或无最终回执时，即使还没有 `test.log`，下一轮也须重启同一受管设备以释放遗留桥接会话，保留 UUID、构建产物和完整失败锁；后续构建/安装失败不能遮蔽该记录。未发起启动的故障、已进入夹具后的拒绝不新增恢复需求，成功测试才解除历史自动化恢复需求。初始化超时先区分启动回执与正式账本提交，按需对本轮进程做有界采样；若采样显示可访问性处理且连接了本轮 Device Hub 显示，可先隔离显示连接再从最小启动用例复验，不据此推断所有超时的唯一原因。已有制品只可辅助诊断，不能替代当前源码的正式局部回执，不为定位重复完整构建或验收。恢复判定的局部回归使用 `node --test --test-name-pattern '恢复需求|初始化启动|未启动原生' scripts/tests/ios-debug.test.mjs`，CI 的 check:app 执行同一文件。

完整检查不接受单用例过滤，仍重新生成资源、执行原范围与门禁；默认新建独立模拟器，也可通过 `--session` 借用本轮受管设备。局部证据只用于启动资格，不替代完整结果，也不消费旧测试结果。多个故障分别修复时，可以重复传入 --from（1 至 32 份）；每份回执均须匹配当前输入及适用环境，重复路径、失败/过期回执拒绝。覆盖按每个目标自己的最近失败时间判断，允许先修 A 再修 B，无须因 B 后来失败而重跑已修复的 A；不能用无关新回执搭配目标的旧回执解锁。CI 原生分支使用同一约束：先执行最低层 App 测试取得新回执，再进入原生完整验收并 finally 关闭会话；失败时按对应目标局部修复，不增加无关原生烟测。

本机 `ci:ios-app -- run --results PATH --group macos --session SESSION` 可重复追加 `--from REPAIR_DIRECTORY`，将其他失败目标的局部修复证据传给完整原生入口；默认 App 测试前置保留，额外最多 31 份。修复证据按独立角色归档，避免同名报告覆盖；原生入口仍核对当前输入、环境、失败目标与时间，脚本阶段失败不能由 App 测试绿色代替。该参数不适用于非完整套件或远端执行，不解除完整失败锁。

无需模拟器的局部检查由 [ios-checks.mjs](../../scripts/lib/ios-checks.mjs) 白名单统一定义，命令、失败目标和证据校验同源：

```bash
npm run debug:ios-app -- list
npm run debug:ios-app -- check --check app-tests --file src/domain/money.spec.ts
# --name 为 Vitest 的 testNamePattern；必须实际命中并通过，不接受零用例
npm run debug:ios-app -- check --check app-tests --file src/domain/money.spec.ts --name 'multiplies price and quantity'
npm run debug:ios-app -- check --check script-tests
npm run debug:ios-app -- check --check app-build
npm run debug:ios-app -- check --check probe-build
npm run debug:ios-app -- check --check resources --target source
# simulator/device 资源检查需要对应 Release 产物；编译故障可不启动模拟器
```

Vitest 精确修复回执只覆盖报告中实际通过的测试；只有无过滤且整组通过才覆盖 check/app-tests。资源检查区分 source/simulator/device；原生构建区分 App/Debug 与 DictionaryTouch/Release，安装与初始化故障通过相同目标的原生局部运行重做该阶段，不能仅用命中缓存代替修复证据；实际重做并通过后恢复局部缓存，故障记录仍保留用于判断必要复验。缓存恢复独立记录在 schema 2 的可选 cacheRepairs 中，按当前输入、原生环境及构建/安装/初始化阶段匹配；回执须晚于该阶段完整失败时间，旧输入、其他环境、错误阶段和工程检查均不能恢复缓存。再次完整失败会使此前缓存修复失效。恢复缓存不会修改完整失败状态、次数或跨套件限制；若后续局部命中缓存，应保留并通过 --from 提供之前真正重做失败阶段的回执，不能用缓存命中冒充新的阶段修复。

create 输出 `SESSION=...` 与本轮模拟器 UUID。将输出的绝对会话路径保存到当前终端变量 `IOS_DEBUG_SESSION`，再执行以下命令；不能填入用户已有设备或其他轮次的 native-* 目录。

```bash
npm run debug:ios-app -- run --session "$IOS_DEBUG_SESSION" --case NativeTests/NativeSqliteTests/testRejectUnownedTestContexts
npm run debug:ios-app -- run --session "$IOS_DEBUG_SESSION" --scenario template-tie
npm run debug:ios-app -- run --session "$IOS_DEBUG_SESSION" --scenario interruption-migration-recorded
npm run debug:ios-app -- run --session "$IOS_DEBUG_SESSION" --scenario paging-disable
npm run debug:ios-app -- suspend --session "$IOS_DEBUG_SESSION"
# 将对应局部成功命令输出的 EVIDENCE= 路径分别保存为这两个变量

# 仅按必要影响执行；失败后须覆盖实际失败目标，普通绿色不自动要求全跑
```

- 原生字典场景使用独立的 scenario/…/场景名 覆盖键；失败锁、阶段元数据、回执及日志信号均核对场景名。crud 通过不能替代 template-tie 修复，只有方法名通过也不算场景通过。
- 原生字典场景由 [scenarios.json](../../app/native-tests/scenarios.json) 列出，复用同一 dictionaryProbe 与 SQL 场景，只执行指定组；选择保存在已校验测试清单中，不为生产 App 添加参数。`paging-merge`、`paging-disable` 各执行两项业务触摸及一项键盘就绪前置；前置从原明细搜索控件建立完整键盘、确认原输入仍为空，通过原生“完成”按钮收起软键盘后再返回“记一笔”；文本输入、退格及 Unicode 边界由搜索业务用例验证，不保存业务数据。`merge-relaunch` 执行对应两项触摸，`merge-cycle` 连续验证取消、确认和重启三项触摸。选择依赖页面状态的单用例 test10/test12/test14 时，也显式携带 test09/test11/test13 前置；新增/改名用例 test01–test05、搜索用例 test11/test13 及其依赖链都先执行键盘就绪前置。输出与回执列出实际执行项，其余触摸用例通过共用夹具准备必要数据。

#### iOS 交互与容量复核

沿用 `npm run debug:ios-app -- run --session <本轮独立会话>`，单例选 `--case`，场景选 `--scenario`。`ios-review` 核查六个实际页面在 360×800、390×844、430×932、844×390 下的名称、溢出和网络资源，以及状态栏、Dynamic Type 通知和原外壳。`ios-interaction` 分成三个 XCUITest：横竖屏中文/数值键盘、保存可达与草稿保持，竖屏候选搜索/原生日期，横屏候选选择与收键盘后的页头恢复；`ios-candidates` 仅组合后两项，保留前一项已选分类的真实前置。仅低高度“记一笔”键盘状态临时让出固定页头，短屏候选工具条允许随列表滚动，避免工具条独占可见区；正常页面与样式仍按原基线；hosted DOM 证据与原生触摸分开登记。三例单独或组合均使用 `interaction-61`、`interaction-62`、`interaction-63` 及对应逗号列表夹具，准备阶段只读捕获空账本、安装/数据集归属、schema、字典和偏好参照，不预写草稿；结束后核对正式业务未写入、字典与无关偏好未改写、草稿属于原数据集，以及实际单价 `12.3456`、候选分类与最终收支类型。SQL 回读 `IOS_INTERACTION_SQLITE_VERIFIED cases=...` 与每例既有触摸完成信号同时必需，仍须通过日志、原封存、安装基线及受管命令终态校验；任一缺失不得登记成功。准备拒绝残留草稿/旧回执，回读拒绝跨安装/数据集、错场景、残缺或链接回执，均不改原数据；这组脚本回归不替代三例实际 XCUITest。对应回归由 ios-debug.test.mjs、ios-measurement.test.mjs 自动纳入本地和远端常规工具测试。不声称模拟器执行了 VoiceOver 或真机硬件检查。合法备份密码字段不属于登录入口，外壳守卫按真实登录/组织/管理路由及入口拒绝。

容量采用 `--scenario scale-10000` / `scale-100000`，支持 `-prepare`、`-native`、`-pages`、`-cold` 子阶段；冷启动定位可用 `-cold-01` 至 `-cold-05` 仅运行对应单例，例如 `--scenario scale-10000-cold-02`。单例回执标明样本序号并明确不采 RSS，避免调试时引入无关进程观测；只能作为局部修复证据，完整专项仍须同轮五份样本，不拼接单例成功。完整场景按准备、原生服务、页面、冷启动执行；局部失败仅复验目标子阶段，不重复完整验收；冷启动自动化故障按既有恢复规则仅重启本轮设备，保留 UUID、数据与有效构建缓存。Capacity-Release 独立缓存与 Bundle 不替换普通调试 App；安装绑定本轮设备、会话和新旧制品。夹具在检查摘要、schema、数量、datasetId、完整性/FK 后才原子安装至隔离 App 的动态沙盒；外部安装、错误回执和未关闭旁路文件拒绝接管。已验证兼容的夹具可复用，测量仍绑定新运行/源码/制品，不拼接多轮局部成功。 换库前在受管容量沙盒内先登记精确操作，绑定会话、设备、独立 Bundle 与操作 UUID；先写权限 600 的会话/设备专属临时登记，完整写入、刷新并关闭后原子发布正式登记，发布前不复制数据库。未发布的空/半写入文件只在受管沙盒的精确专属路径清理，并校验文件类型、所有者、权限、链接数及大小；其他会话文件和非法正式登记不自动删除。登记失败不复制，复制/权限/校验/提交失败清理本次暂存文件并保留原库，清理失败保留主失败与登记。下轮先停止容量 App、重验安装和沙盒归属，再清理登记的残留；原子重命名后中断只清登记，不回滚已提交主库。跨会话/设备、非法登记及链接拒绝，未知文件不按前缀删除。

合成夹具经正式迁移/服务生成，含两类收支、365 天、退款与约 10% 回收站（保留原始支出用于编辑），500 条有界批次；回收期限从执行时计算。服务阶段观测真实 SQLite 与加密备份/保护恢复；页面阶段通过正式路由、表单和桥调用测量明细/筛选、保存、总览、五种时间粒度、九类支出和五类收入，等待当前查询与渲染、回读精确金额，不能以旧快照或服务耗时代替页面。冷启动从进程退出计至可用表单，XCUITest 结果标为自动化保守上界；同一测试会话内执行五个独立用例，每例输出一份带序号的原始样本。汇总必须恰好收到本轮同源码/制品/设备/数据集的五份无重复样本，缺失或混轮拒绝，不拼接旧结果。模拟器记录基线提交、实际工作区源码摘要和 workingTree 标记，不把未提交源码冒充已验证提交；服务取 3 次、文件 1 次、页面各 1 次、冷启动 5 次，仅为开发观测；App 与唯一关联 WebContent 的 RSS 合计单列，不能混入其他任务或冒充真机门槛。

容量 native/pages 单例预算 600 秒，prepare/cold 及其他单例仍 60 秒；冷启动每例先终止目标 App，再测量真实启动，不预启动目标 App；每轮临时 xctestrun 将失败诊断策略设为 Never，与命令行选项一致；容量 UI target 的 PreferredScreenCaptureFormat 显式设为 screenshots，避免全程录屏竞争启动时的合成/GPU 资源，hosted target 与缓存原清单不改写，失败截图、原始日志及失败状态仍保留。每例单独计时，表单就绪等待使用从启动前起算的 55 秒剩余预算并预留 5 秒收尾，不在 60 秒单例外追加等待，也不扣除慢启动耗时；自动化启动和收尾各受既有 180 秒约束，不能把三段压成 90 秒命令上限，也不延长 900 秒局部整轮预算。收尾仅接纳正常退出，或退出码 3 且明确返回 found nothing to terminate 的已停止终态；该预期终态不先触发异常取消，其他退出、超时及取消仍失败，补偿异常保留具体原因。既有构建/安装/初始化预算累计、失败锁保持。普通 smoke 使用 App scheme 的 NativeTests，不加载 Capacity scheme，日常检查不暗中跑大数据。启动失败先对照 XCUITest launch/自动化会话、WebKit 进程启动/导航与 SQLite 就绪时间；必要时用同一隔离安装包直接启动并短时采样定位，诊断启动不计性能通过，不清空缓存或改变其他服务。冷启动清单/收尾回归由 ios-capacity.test.mjs 的“逐次测试清单”“容量收尾”“冷启动五单例”覆盖，共享执行器沿用 ios-ci.test.mjs 的超时/取消/嵌套清理回归。当前登记 `ui-ios-interaction`，规模专项已接入同一 CI 规划/对账入口；PR 按变更选择原生交互，规模仍按需触发。

真机执行器为 `Capacity` Release scheme，两个测试 target 支持 iPhone SDK，原有模拟器守卫不放宽。可信 Mac 按[容量配置](../architecture/environment-configuration.md#离线-app-原生测试配置)设置独立 Bundle、名称及目标设备，签名后执行同组 XCTest，冷启动不挂调试器。`node scripts/ios-capacity-report.mjs receipt.json native-test.log report.json [device-capture.json]` 只消费一次真实成功输出，不触发重跑、不覆盖旧报告。device 报告必须绑定同一运行、源码、制品、夹具和设备，要求干净工作区的 Release 候选，包含端到端时间窗、至少 30 次交互/各 5 次重操作、完整窗口 App/WebView 组合内存与正确性结论；缺项、样本不足或环境不符拒绝通过。组合内存同样绑定运行、源码、制品、设备和规模；冷启动连续测量段的进程缺席必须显式标注，不能用零值掩盖其他操作缺测；MB 按十进制计。服务计时、协议单测和未签名编译不证明真机性能。V14 真机容量、VoiceOver、文件选择/分享、锁屏/重启等随 T17 最终候选集中执行，未完成前保持待验证。

局部 UI 预启动将 App 的原生 stdout/stderr 写入本轮 `app-stdout.log` / `app-stderr.log`（600）；只在受管模拟器及本机私有证据目录保留，不开启远程 Web Inspector。候选原生命中检查使用实际节点类型与可见区域，不能仅凭 WebKit 的 isHittable 点击被工具条或固定栏盖住的行。

协议/隔离回归用 `node --test scripts/tests/ios-capacity.test.mjs`；换库局部选 `--test-name-pattern '容量登记|容量换库'`，用真实 SQLite/文件及创建后写入前、半写入、发布前后、复制后、提交后的子进程强杀验证恢复，并覆盖部分写入与清理同时失败后的重试，不启动模拟器或重复规模观测。外观通知乱序与释放、容量夹具及原设计基线使用对应 App Vitest 局部文件。采样停止或部分证据落盘失败仍尝试停止隔离 App，保留主失败与补偿失败，不能改记测量成功。

#### 统一套件、按需 CI 与最终验收

公共 runner 在生成实际计划时检查 App 锁文件的下载地址（单独读取登记或判断路径不要求存在依赖锁文件），只接受 npm 官方 HTTPS 源，拒绝私有镜像、HTTP、带凭据或查询参数的地址，避免到安装阶段才等待超时；变更下载地址时核实原版本及 integrity 不变，不据此升级依赖。

[套件登记](../../config/ios-ci.json)统一维护本项目已有检查的执行类型、Linux/macOS 归属、固定范围、专项影响路径、测试文件排除及确有覆盖关系的去重。登记只接入离线 App 的现有执行器，不注册旧 Web、Java、PostgreSQL、服务器部署或尚未实现的真机性能能力。[CI 规划器](../../scripts/lib/ios-ci-plan.mjs)、[执行与对账](../../scripts/lib/ios-ci-run.mjs)由本地和远端同一入口调用；不查询历史绿色或计费，不继承旧提交的验收结论。

验证范围分为日常局部、固定集合和变更专项。日常局部用 `debug check --file/--name` 或原生 `--case/--scenario` 选择目标；固定集合定义该集合一旦执行就必须完成的内容，不表示每次保存、提交或推送都执行。`change` 则按本轮变更选择固定工程集合及必要专项。本地 `plan` 只规划不执行，须显式调用 `run` 才开始检查；远端 PR 的 `prepare`、`run`、`result` 由工作流自动串联。

变更基础套件、固定范围或按变更选择规则时，沿 `registry/selectSuites/executionMatrix` 的所有测试消费方检索精确清单断言；当前分流消费方同时包括 ios-ci.test.mjs、ios-delivery.test.mjs，矩阵消费方还包括 ios-verification.test.mjs，不能只验证规划器所在的测试文件。先复现失败断言，再覆盖受影响消费方的定向用例，保留纯单测不扩大原生/UI、实现和混合变更不漏专项以及本地/远端/固定模式的安全基础项。精确预期按已确认契约维护，不从被测登记动态生成预期，不用放宽为子集断言掩盖漏项。仅改这些测试断言时不启动模拟器或重复完整验收，远端仍运行登记的常规工具回归。

影响分析以套件为选择单位；本地 UI 交付证据可按实际用例汇总。例如 App 改动通常会选中 `app-common`，它会运行全部 App 单测及工程检查；`.spec.ts` 变更不因此额外选中 UI 专项。需要快速定位时先用日常局部入口，不为生成正式 CI 报告重复已经充分且适用的局部验证。

| 范围 | 实际覆盖与使用条件 |
| --- | --- |
| `pull-request` | 远端常规：共同祖先到实际 head 按变更选择 Gitleaks 密钥、actionlint 工作流质量、工具回归、App 工程、必要的未签名 iPhone SDK 编译及审计；不创建模拟器。`localRequired` 列出按变更需在本地执行的原生专项，`deferred` 保留未在该计划执行的影响范围，均不计为通过 |
| `change` | 默认本地按变更选择常规及必要原生/UI 专项；完整触摸、容量和安装留在 deferred，仅明确请求或最终候选执行。`--execution remote` 只选常规并列出 localRequired；同一专项合并多条理由 |
| `scripts` | Linux/macOS 验证工具回归、Gitleaks 密钥及 actionlint 检查；不编译 App、不启动模拟器 |
| `app-common` | 常用固定工程套件（根目录 `npm run check:app`）：全部 App 单测及同次执行的 V8 覆盖率、验证工具回归、类型检查、随包资源与探针构建、资源/设计门禁；不启动模拟器 |
| `common` | 固定常规范围：Gitleaks、actionlint、App 工程、未签名 iPhone SDK 编译及依赖审计，不启动模拟器；可本地或远端执行 |
| `app` | 仅本地：App 工程、未签名 iPhone Release 构建及原生 SQLite 集成；不包含完整页面触摸 |
| `final` | 仅本地最终集中验收：App 工程、Release 构建、原生 SQLite、完整原页面触摸、两种规模模拟器专项及依赖审计；固定最小门禁不能被登记删除或由局部替代 |

| `install-gate` | 仅可信 Mac 显式提供安装材料时执行，未接入自动触发；缺手机/报告/签名或候选不符保持未完成，不能由工程绿色兜底 |
| `workflow-quality` | 固定 actionlint 检查全部工作流的语法与表达式；每次按变更计划及固定集合必需，不启动设备 |
| `secrets-history` | 本地显式完整已获取历史扫描；`final` 必含，不在日常 PR 隐式重扫全部历史 |
| `dependency-audit` 或其他登记套件名 | 本地可只规划单套件；远端除上述范围外仅提供独立依赖审计，避免引入多套入口 |

本地自动门禁由 [ios-local](../../scripts/ios-local.mjs)安装和组织，专项仍复用原有 plan/run/result 与 [local-gate](../../scripts/lib/ios-local-gate.mjs)，不另建测试执行器。首次在已核实的功能分支执行：

```bash
npm run setup:local -- --base codex/offline-ios-app
npm run status:local
npm run verify:local
npm run push:local
```

`setup:local` 将本仓库 Git 挂到完整的 `.git/codex/hooks-*` 受管转发目录，不改全局 Git。pre-commit/post-commit/pre-push 加载版本化 `.githooks` 并串联原 hook；其他可执行 hook 按原路径 exec，保留参数、stdin、退出码及基于原始路径的资源定位，原文件不修改。整代文件完整写入后才切换 core.hooksPath；半写不启用，切换失败保留意图并复用完整目录恢复，孤立残缺目录不参与重试；同配置重装幂等，受管文件外部变更拒绝覆盖。旧代可能仍被 Git 进程使用，不在重装时删除。目标分支、原 hook 路径及启用状态保存在 Git 私有配置。它在 macOS 钥匙串创建 Ed25519 私钥，只把公钥追加到仓库变量 `IOS_LOCAL_EVIDENCE_SIGNERS`；读取或登记失败不得默认为成功。私钥、账本、原始日志及本机路径不上传。其他开发者须独立安装并登记自己的公钥，不能复制现有私钥。

| 时点 | 动作与阻断条件 |
| --- | --- |
| 开发定位 | 使用既有单文件、单用例和场景入口；不因保存文件自动启动设备。正式本地 CI 执行前登记未完成尝试，完成后自动登记实际结果，强杀或失败不能沿用旧成功 |
| 提交前 | pre-commit 核验暂存区的登记和生成文档，串联既有 hook；不运行原生专项。允许保存尚未交付的开发提交 |
| 提交后 | post-commit 刷新当前提交的本地待验清单，撤销旧交付绑定；不读取原生工具链、不运行测试，不把待验记成通过 |
| 显式本地验证 | verify:local 按目标分支共同祖先至当前源码计算必需本地专项，只补缺失或失效项；有效项重读报告后复用，不执行 final、完整触摸或容量 |
| 推送前 | pre-push 重新读取目标分支、当前 HEAD 和证据，缺失或失败则阻断正常功能分支推送并给出补验命令；只核验，不自行启动长测试。notes-only 发布只豁免自身回执引用，混合引用、错误远端或其他提交不豁免 |
| PR 与合并前 | GitHub 分支规则要求 `CI common result` 与 `Local evidence result` 均成功，并要求分支保持最新；PR 核验绑定实际 head/base。本地 hook 在推送前核验证据，不在合并时自动重跑 local-gate；网页和工具合并均受这两项远端必需检查约束 |

`verify:local` 是显式补验动作，可能启动命中的独立模拟器；没有命中本地专项时不读取 Xcode/runtime，也不启动设备。普通文档、无关脚本及纯单测由登记选择常规检查；混合实现变更仍须选择真实影响项。裸 debug 单例只覆盖实际通过项；符合下述粒度与隔离规则时可汇总为登记 UI 套件，不把它当作 final 或完整 touch。

本地测量分为交付绑定、专项输入和 UI 用例输入：交付签名仍绑定精确 head/base/tree 与套件定义；专项摘要不含文档、路由规则或工具回归源码，但包含实际执行器、制品源、原生配置、夹具及必要工具链。SQLite 集成仍绑定 Vitest 配置，纯受管启动不绑定它；常规检查仍对当前提交执行。Swift 用例摘要包含自身、可达辅助、前后置及类级声明；函数引用、字符串插值和共享归属守卫均参与影响，不能仅凭方法所在文件全选，也不能忽略共享辅助。普通 TS 先用已锁定的 TypeScript 解析器构建 AST，识别导出/重导出、接口、类型别名、类、命名空间及 declare 契约；分离声明后的 export default 和 export = 赋值导出同样保守保留，注释、换行或别名不能绕过。其余局部纯类型差异经 Node 内置类型擦除/转换后比较；解析失败或依赖未准备时保守保留专项。可信元数据工作流只检出基线；核验器确认 PR 身份并发布 pending 后，用 npm ci --ignore-scripts 在 60 秒内安装该基线 App 锁文件中的依赖以准备解析器。安装失败进入同一失败状态出口，不沿用旧成功；子进程不接收发布令牌，不加载 PR 的依赖或执行安装脚本。不执行 PR 内容，不对 Vue 的类型驱动宏作运行等价推断。新增、删除、解析失败或未知路径保守保留专项。可信远端与本地读取同样的差异，并继续取基线/新登记的并集；新代码不能使尚未升级的远端基线自动接受精简规则。

执行输入由 `ios-execution-inputs.mjs` 计算，App/UI 局部封存由 `ios-local-measurement.mjs` 签发；`ios-local-partials.mjs` 转接登记并负责消费校验，真实回读由 `ios-ui-readback.mjs` 校验。容量登记适配器 `ios-capacity-registration.mjs` 仅扩展 Capacity：App/UI 继续原样委托既有签发器，Capacity 通过完整 inputHash 绑定适配器和执行依赖，不按 App/UI 的细粒度摘要豁免。复用时按 AST 语义核对导入绑定、函数参数、非容量分支的条件与直接返回调用，保留字符串值和可选链等运行语义，并核对委托目标与实参未被同作用域的后置声明遮蔽；独立容量块、循环词法作用域、类静态块（含类表达式）和嵌套函数的局部声明不误扩散；静态块拥有独立 var 作用域，外层类声明名称及外层 var 仍检查真实遮蔽。分号、注释、引号、括号、单返回块、命名导入内排序和等价分离导出不使有效证明失效。partialMeasurement、registerPartial、assertCapacityMeasurement 三项必须具备正确的具名导出；缺失、改名、默认导出冒充、重复导出、类型导入、未知转接及顶层副作用均拒绝。适配文件或链接异常不能作为旧版豁免；“适配层引入前的验证脚本结构”仅指这套测试工具的历史结构：入口明确将两项登记 API 指向原签发器，且完整消费依赖图无直接/间接适配引用，才能复用其仍有效的历史测试证明。任一声明依赖缺失时拒绝识别，不将未知模块当作无适配引用；依赖齐全后再只读核验，不补写旧登记。未知计算导入、越界或无法确认的历史路由不放行；不执行旧源码来猜测。容量独立分支变化不扩散到 App/UI。混合模块只排除明确的只读消费部分：`ios-ci-run.mjs` 的受控边界以下校验器，以及 `ios-verification.mjs` 中 AST 识别的三项证据读取函数及其专用导入；命令执行、状态登记、完整失败锁和未知顶层代码仍绑定输入。解析器未准备、语法或边界未知时保守绑定整个文件。修改消费校验不会自动作废相同执行的原始证据，但仍须按当前更严格规则重读；修改执行器、执行依赖、App、夹具或相关用例仍使对应证据失效。 场景依赖由 `ios-scenario-dependencies.mjs` 对明确隔离的 iOS 交互扩展划分：仅三个交互用例绑定专属夹具模块；其他 UI、原生 SQLite 和受管启动不会因该模块独立变化失效。共享选择器/夹具分派只允许投影掉已核实的完整三例专属分支，独占导入、选择条件和分支布局均须精确匹配，并检查伴随夹具目录中的直接/动态导入；共享逻辑、额外导入、未知分支或投影规则自身变化仍保守失效，不按文件名一律忽略。二进制资源保持原字节。构建层有独立输入：仅改选择器/夹具不要求重编译 App、runner 或重建模拟器。补验前先核对真实测量影响，区分未执行与历史成功已失效；不自动重复完整验收。

既有细粒度 v1 封存通过一次固定编码兼容：`config/ios-measurement-v1.json` 保存四份旧模块的原文与摘要，仅作为哈希编码数据，不加载或执行；源文摘要和提取后生产者摘要同时受代码中的固定摘要约束。只有生产逻辑与已核实基线一致时才重建旧编码。新增测量依赖划分及签发前只读检查，仅按固定依赖策略中的精确逆变换核对：逆变换后的整份生产者源码必须匹配原固定 SHA，策略文件自身也须匹配内容固定值；不满足时绑定完整当前生产者，切换 v2 输入并拒绝旧证据。原 v1 配置、生产者摘要与兼容锚点不刷新，旧源码与逆变换片段只作数据，不执行。不得通过刷新固定摘要追认真实执行变更，也不补造旧报告、封存或基线。该兼容不是旧格式证据的通用豁免。`ios-equivalent-evidence.mjs` 只从当前实际输入重建已核实的细粒度与过渡粗粒度两种 v1 编码；重建的细粒度值必须等于生产摘要，才能承接等价的过渡摘要。相同等价关系同时用于成功、失败、取消、未完成和正式索引的路由，不只恢复旧成功；真实执行变化及未知生产者版本不获得别名。

原生 App/Debug 与 UI 局部任务在执行前先写入既有 `ios-verification-state.json` 的 localAttempts，再发布本轮 `local-measurement.json`；登记保存逐用例输入、开始时间、宿主/环境和会话归属，完成或取消时保留终态。已登记任务须以登记的成功状态、非取消标记及一致完成时间为准；重算结果封存不能覆盖登记中的失败、取消或未完成。UI 准备夹具后另绑定同一安装的受限空账本基线；新格式成功回执同时封存覆盖键、阶段记录及原始日志；UI 另封存对应夹具和 SQLite 回读摘要，不能只改阶段或覆盖声明就伪装修复。原生 hosted XCTest 保留目标用例/场景及实际通过日志，不将其当作外部 UI 触摸。两类结果均须关联外层命令成功终态，外层失败、取消、未完成及本人仍持有收尾锁均拒绝。 UI 回读须从结果的真实选择器推导夹具协议，精确匹配字典、收支、个人配置、生命周期、明细、报表或数据管理实际产生的 SQL/文件回读标记及用例序列；缺项、错场景、多余或乱序标记均拒绝。未登记实际夹具/回读协议的范围保持待验，不伪造字典标记代替。签发器在登记通过前先检查回读与触摸完成信号；完整入口的同输入或跨消费版本 `--from`、局部汇总、正式 CI 归档统一重读原始封存，不以完整输入相同豁免日志、基线、宿主/会话/设备归属和外层成功终态。内部结构读取与完整消费校验分层以避免递归；无封存的工程检查仍须匹配当前完整输入。

Capacity 不按结果自报的 scheme 或选择器豁免：既有 App/UI 登记优先，缺失或损坏也不能改名走容量入口。Capacity 在现有执行前登记入口先写入同一验证状态的独立 capacityAttempts，再发布本轮 local-measurement.json；绑定目标、实际用例、完整输入、宿主/环境、会话/设备、原外层 invocation 路径和 ownerPid，重复或与 App/UI 登记冲突时拒绝覆盖。消费时逐项核对权威登记与本轮文件，并核对执行前 capacity-context.json、同会话/设备的安装归属，以及当前源码/制品/数据集一致的完整原始报告；共用正式规模校验器检查准备、原生、页面、五次冷启动、时间窗和组合内存样本。局部结果和原外层命令均须成功且时间有序；失败、取消、未完成、命令归属错误或原命令仍持收尾锁均拒绝，不从目录时间猜测或补造关联。缺少这组登记的旧容量报告只作历史，不补写登记或重算旧摘要。局部容量阶段仍供调试，不能作为完整 `--from` 证明；通过容量协议也只提供实际测量的容量用例覆盖，不承接未封存的通用构建等声明。

CI 收集步骤只暂存原件；发布套件成功前的 validateReports 与后续归档对账必须调用与 --from 相同的原始局部证明校验。Capacity 不仅校验规模报告，还须核对上述登记、归属和外层终态；UI 同样核对原始封存。归档逐字节比较原受管文件，不允许仅重算归档摘要代替原证明；相关检查在成功发布前完成，不能先签发绿色再等待后续发现。

local-gate 重读登记、结果与原日志，统一拦截原生和 UI 的相关新失败、取消、强杀及损坏。无关旧文件 JSON 损坏只记录隔离诊断，不阻断有效专项，也不把损坏文件当作成功；已登记任务的文件缺失、截断或会话损坏仍按登记范围保留失败屏障。测量路由必须包含非空且合法的用例/摘要、归属、环境和时间；空对象、数组或坏摘要不作为有效登记。旧 localFailures 在完整输入及环境匹配时继续生效，只有有效权威登记以相同目标、完成时间和当前或已证明等价输入完整承接同一失败时才去重，不能只因路径存在或 repairedAt 就忽略旧锁。结果丢失、截断或测量损坏时，统一优先采用登记的失败目标与完成时间；已知只失败一项时不扩大为整轮，也不重置失败时间。负结果按登记中的每个相关目标独立路由，不先按成功可复用摘要过滤。混合登记中即使部分目标仍匹配，其余目标的失败、取消、未完成和结果丢失仍保留原目标/时间屏障；无明确失败目标时覆盖该登记全部相关目标。源码回退或只修复其他目标不能复活旧成功；未知输入的成功不复用。当前目标在屏障后重新验证可建立当前有效证明，但不据此宣称历史执行等价或删除其失败。正式索引对所需套件的负终态、取消与未完成同样保留时间屏障，不因摘要变化丢失。权威验证状态本身损坏则拒绝签发，不自动清空。原始失败、完整失败锁和次数不删除。

UI 只汇总同会话/设备、环境和基线的有效证明，各份运行须独立完成选择器规定的前置、实际目标及数据回读，不跨数据集拼接或从失败运行摘取绿色步骤。原生局部成功可修复匹配的失败目标，使仍有效的原生正式证据恢复可用，但不能替代完整 native-sqlite 集成；场景和恢复阶段按各自覆盖键匹配，其他单例不能代替。构建/安装/初始化等阶段故障必须有失败之后真实重做该阶段的通过证据，缓存命中不算修复；较晚用例通过也不能仅凭时间解除未修复的非用例阶段屏障，正式证据同样须有对应阶段的实际覆盖和成功时间记录。 失败发生在 UI 基线捕获前时，仅允许登记的准备阶段按同会话/设备、相同用例输入及真实阶段重做成功定向修复；用例或回读失败仍须相同基线。 受管重装更换空基线后，不跨基线拼接局部结果消除旧读回故障；应在新基线执行受影响 UI 正式专项的全部目标，并用其真实阶段和最终回执核验。完整入口消费已封存的局部修复证据时，也执行上述当前范围与原始封存复核；没有封存的工程检查仍须匹配完整当前输入。局部修复不将原失败报告或完整专项状态改为通过。范围不明的正式套件失败继续保守阻断旧局部结果。旧输入、错误归属、缺项、跳过、篡改和未知旧格式均不通过；旧回执不补造新摘要。

`status:local` 返回 `missingCases` 及已核验的 `proofs`。UI 已有部分有效证据时，`verify:local` 明确停止并列出缺项，避免自动把整套再跑一遍；先按现有单例/场景入口补齐缺项及必要前置，再核验汇总。不能安全独立执行的连续链仍按原场景完成，不强行跳过前置。只有缺失/失效项会被补验，证据核验本身不启动设备。真实 UI/原生实测与最终候选仍按各专项执行，本地协议回归不证明页面或安装通过。粒度回归入口为 `node --test scripts/tests/ios-measurement.test.mjs`；该文件由本地及远端常规工具回归自动发现。


本地证据索引由独立文件完整写入后原子发布，保存同输入的尝试顺序及失败，不通过覆盖共享锁或回退旧绿色恢复。复用先核对测量输入、当前套件定义、原始报告、宿主/Node、Xcode/SDK/runtime、阶段和清理；文档及提交元数据变化允许重新绑定，执行源码、测试配置、依赖、执行器或夹具改变则对应证据失效。Python __pycache__ 及 .pyc/.pyo 是生成物，不计入测量源码；实际 .py 源码与执行位仍绑定。原计划和原报告不改写；缺少新指纹的旧格式证据只作历史。每次核验保留独立 local-readiness 记录，不解除完整失败锁，不生成完整候选。手动精确核验仍可使用 `ci:ios-app -- local-gate --results PATH --input JSON`；该兼容入口只接受同提交原始证据。

推送将签名回执发布到 `refs/notes/ios-local-evidence`，不进入 App 源码树，也不产生“提交回执后再次失效”的循环；正常快进保留回执历史。回执绑定仓库、提交、目标基线、Git 树、精确专项、输入/报告/环境摘要和签发时间。七天签发窗口到期只要求重新核验并签发，输入有效时不重测。失败回执也会阻断；回执在本机尚未发布时，远端无法感知其变化。`push:local` 在没有新提交时也能发布或刷新回执，并请求现有 PR 的轻量核验；有效且内容相同的签名回执不重复发布。计费或排队受阻不阻止本地验证和提交，远端受阻保持待验，不伪造合并资格。

[可信元数据工作流](../../.github/workflows/local-evidence.yml)只执行受保护基线中的验证器，PR 文件只作为 Git 对象读取；合并共同祖先的改名双向路径按同一选择器处理，同时保留基线和候选策略要求，PR 不能自行删除应跑专项。公钥来自仓库设置，不接受 PR 自带信任声明。必需项缺失、失败、取消、非法跳过、签名错误、旧提交/基线、过期或重复项均拒绝；没有本地必需项时明确判为不适用。核验完成前重读 PR 和 notes 引用，过时快照不得发布成功。`pull_request_target` 的写权限仅发布状态，不检出或执行 PR 代码；仅安装可信基线 App 锁文件中的依赖以准备解析器，不安装 PR 依赖、不执行依赖安装脚本或启动设备。签名证明授权本机签发了结果，不独立证明测试实现无误；当前来源为 GitHub Actions，仓库管理员及有权修改工作流/规则的人员属于信任边界，未配置专用 GitHub App 的来源隔离。

套件说明由登记生成到下面的唯一受管区；运行 `npm run ci:ios-app -- docs --write` 更新，`docs` 只检查。生成器不改正文、不自动暂存；pre-commit 检查暂存版本，远端规划前检查实际版本。影响路径完整性仍需维护回归，生成表不替代业务覆盖审查。

Gitleaks 使用默认规则，禁用行内 allow 注释、外部忽略文件及宽泛目录豁免；唯一例外登记在 [ios-security-exceptions.json](../../config/ios-security-exceptions.json)，必须精确匹配文件、规则和命中行字节 SHA-256，含原因及 UTC 到期日。过期、重复、内容变化或当前已不命中的遗留例外均失败；历史命中按原提交内容核验，不能用当前文件覆盖历史事实。当前仅允许原设计基线 tokens.css 摘要这一非凭据误报，不修改基线原文。输出不含匹配值和代码片段。上述规则变化须同步精确反例，不能扩大豁免来通过。新增安全回归由 `ios-security.test.mjs` 自动接入既有工具套件，实际 Python 夹具覆盖下载/缓存/原子发布、工具失败、范围、路径及例外失效；本地证据回归由 ios-ci.test.mjs 的“本地必需证据”“本地核验真实 CLI”覆盖。工具测试不启动业务服务或模拟器。登记文档生成沿用本节唯一受管区；定时依赖审计的范围与触发规则见下文，不另设安全专项执行器。

install-input JSON 的 ci/candidate/signature 为对应文件路径，devices 为两份 `{receipt, observation, capture}` 原始真机材料路径数组（含 1 万/10 万条）。ci 必须是现有结果目录的 ci-result.json，入口重新对账其计划、实际原报告及同源码完整候选；候选工作区不干净、签名过期、缺设备/指标、Debug、模拟器、错误候选及稳定性失败均拒绝。1 万条硬指标必须通过，10 万条仅性能超目标可观测；原始材料和逐项判定保留到 install-report.json。也可先 `plan install-gate`，在该结果目录显式放置 install-input.json 后运行 macos 组；不将它追加到普通 final 以自动索取手机/证书。真实性能、安装/升级及 VoiceOver 等仍按最终候选另验，协议测试不代跑。ios-delivery.test.mjs 覆盖空采集/合法零覆盖、性能专项分流、规模来源/窗口及落盘原因；ios-signing.test.mjs 用合成授权和受控 codesign/security/plutil 验证共享授权规则、真实 CLI 提取/拒绝接线和临时文件回收，Linux/macOS 均由普通工具回归自动发现。受控工具不证明真实签名或安装通过；失败锁原因链由 ios-verification.test.mjs 的 T15 用例核验。

机器计划 `ci-plan.json` 绑定执行位置 execution、源码内容、提交、登记、变更范围、必跑套件、localRequired/deferred 与命中理由；执行前后及总对账重新规划，拒绝删减必跑项、旧版本、参数变化或执行中修改源码。执行器复用原命令、受管模拟器和证据锁，同一 macOS 组复用其新建的独立设备，结束时关闭自己的会话。每套件保存运行/失败/完成回执和原报告副本与摘要，不能覆盖已有运行或失败现场；组清理失败也使整体未完成。跨主机只核验携带的原报告，不读取另一台机器的绝对沙盒路径。远端每组按 attempt 独立归档，重跑失败作业沿用原计划制品名；汇总仅采用每组最新 attempt，最新失败/缺失/错误计划不能回退旧绿色。未重跑的组保留同计划有效报告；job 本身失败或取消仍使整体未完成，历史归档不覆盖。

`result` 逐项对账必跑与实际，生成 `ci-result.json/md`：缺项、失败、取消、额外套件、错误环境/版本/范围、原报告缺失或被篡改均不能通过。原生实际用例、App 单测数量和脚本回归摘要须与原报告对应。由 [报告校验器](../../scripts/lib/ios-test-reports.mjs) 按 mode 核对工程/资源、原生构建/安装/初始化及相应测试、恢复或回读的必需阶段和原日志；原生构建须有实际成功信号，缺少阶段不能靠重新计算摘要补足。受控测试夹具的外层命令起点不得晚于内层测量起点，结果制备耗时不能倒置包围关系；真实外层晚启动仍须拒绝。脚本调试、完整入口和 CI 共用 TAP 执行与校验：必须有实际通过用例，失败、取消、TODO、空执行及计数不完整均拒绝；Linux 仅允许套件登记 `scriptSkips.linux` 中明确列出的 macOS 专用测试，逐项 SKIP 名称和数量必须对应，重复、未登记及错误平台跳过均拒绝，macOS 不允许跳过。独立脚本 runner 清除继承的 Node 测试上下文，输出上限 16 MiB，超出或执行失败不能取得成功回执。单组通过不代表整体完成；只有 `final` 全部必需项及组清理通过才输出完整候选标记。[共享进程清理器](../../scripts/lib/ios-processes.mjs) 同时供外层 CI 与内层 App 命令使用：每个外层命令建立独立的私有父子登记，内层启动时持续登记本分支进程组，取消后新建的补偿组也归属原调用。补偿工具须在进程组登记完成后才经内部管道的单一 GO 换行帧放行；不等待双工流 EOF。无帧或半帧即 EOF、非法帧均拒绝，父进程在放行前退出时工具不启动。独立诊断通道记录等待、帧接收、实际子 PID 及退出，写入同一受管登记且不混入工具 stdout/stderr；迟到轨迹不能复活已关闭登记。超时/取消同时采集 PID/PPID/进程组快照以覆盖未使用执行器的现有后代，再通知直接进程组退出；最终清理先关闭当前登记分支，读取其中仍活动的组，再强杀内层和外层组。关闭标记写入失败仍继续读取并清理已登记组，同时保留清理失败；不增加等待或延长宽限。关闭后拒绝续建，其他分支和其他调用的范围不能混用。快照只读取进程标识，不读取命令参数：Darwin 通过既有 Python 工具调用 libproc 读取 PID/PPID/PGID，不再启动 ps；其他平台沿用数字列 ps 查询。原生枚举有容量与重试上限，仅接纳 ESRCH 退出竞争，权限、截断或元数据异常仍保留失败。其中进程查询最多占用 2 秒，实际取查询上限与剩余清理宽限的较小值，仍计入既有 10 秒宽限；读取失败保留清理失败，不能判成功。重复停止不延长宽限，完成后迟到回调失效；已耗尽的创建补偿保持零宽限，不额外扫描或等待。清理直接发送目标信号，不先以 signal 0 探测权限；真实 EPERM 仍失败并记录目标进程组和信号，只有 ESRCH 表示已退出。内外层收尾通过同一 finishCleanup 保留原始执行错误在先、清理原因在后；不能让 finally 覆盖超时、取消或非零退出。成功的 simctl boot/launch 请求将本组长期服务交给设备 UUID 的 shutdown/terminate 管理，不在请求成功返回后强杀服务；仍关闭登记并清理其余已登记子组，失败/取消不能使用该交接。普通命令遗留的后台成员仍须清理。正常完成仍保留原退出结果，不扫描进程树；仅回收当前命令自己遗留的直属/已登记组，不清理其他任务。活动索引在叶子完成后摘除，不逐轮扫描已完成的测试历史。私有登记位于 `.local/ios/tmp/ai-agent/ios-process-*`，仅含归属令牌、父子 ID 和 PID；正常关闭后回收，清理失败保留给既有 CI 诊断制品，不作为构建缓存或验收证据复用。JSON/Markdown 是工具本轮产物，不新增开发计划或阶段报告。
