# 个人账单 PWA 开发计划

## 1. 需求来源与目标

- 需求文档：`agent-works/requirement.md`。
- 上游事实源：`agent-works/requirement-closure.md`。
- 设计事实源：`DESIGN.md`。
- 原型依据： `agent-works/prototypes/login.html`、`expense-entry.html`、`reports.html`、`bill-details.html`、`profile-settings.html`、`admin-console.html`；共享样式与交互事实源为同目录 `prototype.css`、`prototype.js`。
- 功能目标：建设一套手机优先、可安装、仅受控内网访问、按单用户单租户隔离的个人收支 PWA，闭环支出、收入、退款/报销调整、字典、明细、报表、管理、导出、注销、部署和备份。
- 已确认技术基线：用户已确认采用 Vue 3 + Vite + TypeScript + Pinia + Vue Router；Java LTS + Spring Boot + Spring Security；PostgreSQL + Flyway；ECharts；Docker Compose。
- 关键实现取舍：用户已确认采用单机同源部署；后端采用模块化单体和关系型精确数据模型；金额使用 Java `BigDecimal` 与 PostgreSQL `numeric`；第一期不引入 Redis、消息队列、微服务或地图服务；共享状态通过 PostgreSQL 和应用事务闭环。该选择以更可控的中国大陆访问、服务端 Cookie 会话和单一部署边界换取主机、补丁和备份运维责任。
- 本次不做：R25-R38、R57、R69 对应的后续或明确排除能力；不重新生成或替换已确认 HTML 原型；不把原型演示数据当成生产 seed。
- 计划输出目录：`agent-works/`。
- 当前完成状态：T1–T29 已按一期内网范围完成；T30 已完成持续构建更新入口；T31 已完成首次环境初始化自动化的本地实现与验证；T32 已完成宿主准备入口；T33 已完成统一日常运维与异机加密副本入口；T34 已补齐替代主机密钥恢复、异机副本演练与公网演进门禁。新的真实服务器宿主安装和初始化、生产数据覆盖/入口切换仍未执行；后续建议和排除项仍按 §3/§6 处理。
- 证据入口：T1–T28 的测试与候选见[部署前报告](pre-release-test-report.md)；T29 服务器、浏览器和用户 iOS 实机确认见[验收报告](test-report.md)。实际源码/镜像/前端制品分别以[部署案例](deployment/cases/intranet-single-host/README.md)为准，不混用历史候选摘要。

### 2.3 后端、数据与部署依据

- 身份和租户只能来自服务端认证上下文；客户端请求体、查询参数和路径均不得提交资产租户 ID。
- PostgreSQL 保存所有业务时间为 `timestamptz`，同时保存按 `Asia/Shanghai` 计算的 `business_date`；货币固定人民币。
- 支出、收入在统一账目表中以类型约束字段集合，调整单独建表并强制关联原支出。
- 服务端会话使用随机不透明令牌；浏览器只持有 `Secure`、`HttpOnly`、`SameSite=Lax` Cookie，数据库仅保存令牌摘要。退出、停用、改密、重置和注销均撤销相关会话。
- 低成本基线为单台 Linux 主机运行反向代理、前端静态资源、Spring Boot 和 PostgreSQL 容器；一期复用用户提供的内网主机，不开放公网；T29 落实主机安全维护、容量、独立端口、内部 CA/终端信任和 RPO/RTO。

## 4. 技术方案

本节及 §5、§8 保留已批准的实施方案与任务输入，用于解释实施依赖；当前实现机制和配置消费链以[技术架构](architecture/README.md)、[环境架构](architecture/environment-configuration.md)为准，页面契约以 [DESIGN](../DESIGN.md) 为准。后续改动在责任文档维护稳定细则，本计划只同步受影响任务、依赖及状态。

### 4.1 工程结构与模块边界

```text
web/                         Vue PWA、页面、语义组件、状态、API 客户端
server/                      Spring Boot 模块化单体
  src/main/java/.../auth     认证、会话、限流、当前用户/租户上下文
  src/main/java/.../admin    用户、默认字典、运行概况、管理日志
  src/main/java/.../dict     八类个人字典和商品合并
  src/main/java/.../ledger   收支、模板、调整、生命周期、导出
  src/main/java/.../report   统一筛选、聚合、下钻契约
  src/main/java/.../job      清理、注销、导出、备份状态任务
  src/main/resources/db      Flyway migration 与人工回滚脚本
deploy/                      Docker Compose、反向代理、备份与恢复脚本
agent-works/                    需求、计划、后续 SQL/测试/开发留痕
```

- 前端通过同源 `/api/v1` 访问后端，避免跨域 Cookie 和额外 CORS 暴露面。
- 后端按领域包分层为 controller、application/service、domain、repository；跨模块只通过应用服务或只读查询接口，不直接跨包修改表。
- 数据库访问统一使用 MyBatis-Plus：Java 仓储只依赖 Mapper 方法，参数化 SQL、动态条件、锁和批量语句统一维护在 `server/src/main/resources/mapper/**/*.xml`；禁止生产代码直接使用 Spring JDBC/JPA 或内嵌 SQL。
- 所有金额、数量、规范化名称、筛选参数、报表口径分别形成共享领域 helper；前后端都执行输入校验，但服务端为权威。
- REST 错误统一返回 `code`、`message`、`fieldErrors`、`traceId`、`retryable`；不得回传堆栈、账号是否存在、租户 ID 或敏感字段。
- 前端 API 客户端统一解析标准 HTTP 状态、字段错误、超时、断网和取消；Cookie 会话失效只执行一次全局跳转/清理，页面主动查询可关闭全局 toast 并使用区域错误态。列表和图表使用请求取消或请求代次，晚响应不得覆盖新筛选。

### 4.2 数据模型

| 表/实体 | 关键字段与约束 | 生命周期与索引 |
| --- | --- | --- |
| `tenant` | `id UUID`、`status` | 普通用户一对一归属；状态索引 |
| `app_user` | 全局唯一 `username`、密码摘要、临时密码到期、角色、状态、`tenant_id`、凭据版本 | 用户名唯一；普通用户唯一租户；停用/注销撤销会话 |
| `user_session` | 用户、令牌摘要、凭据版本、到期、撤销原因、最近使用 | 只存摘要；用户+有效状态索引；到期清理 |
| `auth_rate_limit` | 入口、主体摘要、时间窗、失败计数、锁定到期 | 登录/重置共享数据库限流，避免单实例内存状态丢失 |
| 七类字典表 | `expense_category`、`unit`、`funding_channel`、`purchase_channel`、`location_label`、`income_category`、`payer` 均含租户、稳定 ID、展示名、排序、状态 | 名称规则、启停和历史引用保护；分类支持父子且最多两级 |
| `product` | 租户、展示名、规范化名称、分类/单位默认引用、最近值、状态、合并去向 | `(tenant_id, normalized_name)` 唯一；合并事务锁定冲突项 |
| `default_dictionary_item` | 类型、父项、展示名、规范化名称、排序、状态 | 五类同层等价名称唯一；只复制启用项给新用户，变更不触碰存量租户 |
| `ledger_entry` | 类型、业务时间/日期、版本、支出或收入字段、各名称快照、删除/清理状态 | CHECK 约束类型字段；租户+日期+ID 稳定分页；金额 `numeric` |
| `expense_adjustment` | 租户、原支出、类型、金额、业务时间、状态、删除时间、版本 | 只关联支出；有效累计额在锁定事务内校验；状态索引 |
| `daily_entry_template` | 租户、类型、规范化名称、稳定引用和字段快照、来源账目、最近使用 | `(tenant_id,type,normalized_name)` 唯一；同键原子更新 |
| `user_preference` | 默认资金渠道、明细范围、报表范围、主题、最近填报类型 | 合法值 CHECK；失效引用读取时回退安全默认 |
| `idempotency_record` | 租户、操作、幂等键、请求摘要、结果引用、状态、到期 | 唯一键保证重试返回同一结果；请求摘要不同则冲突 |
| `export_job` | 用户、筛选快照、状态、文件位置、到期、错误摘要 | 受控流式生成；仅本人下载；到期清理 |
| `account_deletion_job` | 用户、状态、申请/执行时间、结果摘要 | 注销可审计且幂等；具体法务保留策略在正式运营门禁确认 |
| `admin_audit_log` | 管理员、动作、对象类型/ID、结果、时间、安全摘要 | 追加只读；不保存密码、令牌或用户账目内容 |
| `product_merge_event` | 租户、源/目标商品、操作者、账目/模板影响数、模板冲突、发生时间 | 强制 RLS、源商品唯一留痕；运行角色只读和追加，不可改写 |
| `job_run`、`backup_run` | 任务类型、批次、开始/结束、结果、处理数、错误摘要 | 清理和备份可追踪；不记录业务敏感明细 |

关键事务：

- 创建普通用户、租户和默认字典副本在单事务完成；临时密码只在事务成功后向管理员展示一次。
- 保存账目与幂等记录、最近使用/付款方快捷新增在单事务完成。
- 商品合并锁定源、目标和冲突模板，迁移引用、合并模板并记录审计后提交。
- 创建/恢复调整锁定原支出及其有效调整集合，重新计算累计金额；超限整体回滚。
- 删除/恢复原支出与调整冻结/重生效在同事务完成；联动永久删除也在同事务完成。
- 报表不维护第一期持久化缓存；直接依赖索引和聚合 SQL，写后无需处理跨节点缓存一致性。
- 租户业务表的主键、唯一约束和跨表外键按适用情况以 `tenant_id` 作为前导归属列；同一业务 ID 即使被猜中，也不能绕过数据库约束关联其他租户。当前一用户一租户，不重复引入无业务价值的 `owner_user_id`。

R3 数据库 RLS 防线：

- `ledger_entry`、`expense_adjustment`、七类个人字典、`product`、`daily_entry_template`、`user_preference`、`idempotency_record`、个人导出/注销任务等租户业务表统一执行 `ENABLE ROW LEVEL SECURITY` 与 `FORCE ROW LEVEL SECURITY`，`USING` 和 `WITH CHECK` 都要求 `tenant_id = nullif(current_setting('app.tenant_id', true), '')::uuid`；上下文缺失时表达式不命中任何行，默认拒绝。
- Flyway 使用独立迁移所有者角色；应用运行角色不拥有业务表、没有 `BYPASSRLS`、不得继承超级用户或迁移角色。备份/恢复使用独立运维凭据，不暴露给应用容器。身份与管理员账号管理表按最小管理职责单独授权，管理员业务接口不得获得绕过账目 RLS 的角色。
- 每个租户业务事务在取得 `CurrentPrincipal` 后先执行 `select set_config('app.tenant_id', :tenantId, true)`，第三个参数固定为事务级；禁止 session 级 `SET`。事务结束由 PostgreSQL 自动清理，连接池归还前增加上下文缺失/切租户复用断言，防止租户值跨请求残留。
- 后台任务按租户拆批，每个事务显式设置同一 RLS 上下文；不得用应用超级租户或关闭 RLS 扫全库。需要全局调度时只从不含账目内容的任务索引取得租户 ID，再逐租户进入受 RLS 保护的业务事务。

Flyway 高权限凭据边界：

- 生产 migration 只由 `deploy/compose.yaml` 中的 `migrate` 一次性服务执行；该服务使用 `server/Dockerfile` 的独立 `migrate` 构建目标，只包含 Flyway CLI、JDBC 驱动和只读复制的 `server/src/main/resources/db/migration/`，不启动 Spring Web、业务 Bean、后台任务或应用 API。
- `server/src/main/resources/application-prod.yml` 固定 `spring.flyway.enabled: false`，常驻 `app` 服务只能使用运行角色；V007 仅向运行角色授予 `flyway_schema_history` 的 `SELECT` 供启动时核对预期版本，不符合即 fail-fast，应用不能自行取得迁移角色补跑。
- `deploy/env/production.env.example` 只声明 `MY_BILL_MIGRATION_DB_URL`、`MY_BILL_MIGRATION_DB_USERNAME`、`MY_BILL_MIGRATION_DB_PASSWORD_FILE` 与对应 `MY_BILL_APP_DB_*` 键名。`deploy/scripts/run-flyway.sh` 从 `/run/secrets/migration_db_password` 读取密码后 `exec flyway migrate`，不得打印环境、命令展开或密码。
- Compose 声明 bootstrap、migration 与 app 三类 secret：长驻 `db` 只挂 bootstrap secret；一次性 `provision` 短时挂三类 secret 创建最小角色；`migrate` 只挂 migration secret；长驻 `app` 只挂 app secret并拒绝任何 `MY_BILL_MIGRATION_DB_*`。宿主机真实 secret 放在 `/etc/my-bill/secrets/`、权限 `0600`，不进入 Git、镜像、构建参数、日志或非密钥 env 文件。
- 发布时先执行 `docker compose run --rm migrate`；成功并核对 schema 版本后才执行常驻服务 `docker compose up -d app web proxy`。migration 失败时一次性容器退出且禁止启动新应用版本；容器删除后迁移 secret 不存在于任何常驻容器，后续升级仅在受控维护窗口再次按需挂载。

### 4.3 接口契约与权限

| 领域 | 主要接口 | 权限与边界 |
| --- | --- | --- |
| 认证 | `/api/v1/auth/login`、`first-password`、`logout`、`password`、`session` | 匿名仅登录；登录/重置限流；错误不暴露账号存在性 |
| 管理用户 | `/api/v1/admin/users/**` | 仅管理员；响应 DTO 禁止账目、金额、付款方、地点字段 |

| 报表 | `/api/v1/reports/summary`、`dimensions/{dimension}` | 统一筛选对象；维度白名单；服务端聚合并返回可下钻值 |
| 导出 | `/api/v1/exports`、`/api/v1/exports/{id}` | 当前用户；筛选快照不可改租户；CSV 防公式注入 |
| 我的/注销 | `/api/v1/me`、`/api/v1/me/deletion` | 当前用户；二次确认后撤销所有会话 |
| 运行概况/日志 | `/api/v1/admin/overview`、`/api/v1/admin/audit-logs` | 仅管理员；概况不含任何用户账目聚合 |

- 普通用户路由守卫和服务端授权同时执行；前端守卫只改善体验，不能代替服务端权限。
- 所有实体查询均从 `CurrentPrincipal` 获取用户/租户，并在 repository SQL 显式包含 `tenant_id`；复合外键或服务端归属校验阻止跨租户引用。
- Spring Security 对 `/api/v1/**` 默认拒绝，公开路径只保留登录与最小健康探针白名单；请求链缺少 `CurrentPrincipal`、认证存储不可用或授权解析异常时 fail-closed，返回 401/403/503 中适用状态，不允许回退默认用户或管理员。
- 应用层租户条件、复合归属约束和 PostgreSQL RLS 三层同时生效；RLS 是纵深防御，不替代 Repository 显式 `tenant_id`。任一层上下文缺失、值非法或设置失败都回滚事务并拒绝请求。
- 修改使用 `version` 乐观锁；冲突返回 `409 VERSION_CONFLICT` 并保留前端草稿。
- 备注接口合同暂定最多 500 个 Unicode code point，用户名暂定 3-64 位可见 ASCII 字符；二者在 T1 契约评审时固化，不改变既有业务流程。

- 文档命令治理：正常重复操作统一收敛到 `environment/release/ops`；多步变更、远程引号、secret、确认/回退或约120字符以上的易错命令必须评估封装，长度不是唯一标准。底层命令只保留实现解释与事故诊断用途。

| `deploy/backup/*`、`deploy/restore/*` | PostgreSQL/导出文件备份、校验与恢复 | 定时及演练 | 备份存储 | 恢复前创建当前快照；演练在隔离环境 |

SQL 约束：所有脚本必须有总体、对象/字段、执行前置、影响范围和回滚注释；生产不依赖 destructive undo。可执行 migration 必须放在 `server/src/main/resources/db/` 供 Flyway 打包和校验，这是相对技能默认 `agent-works/{feature-slug}/*.sql` 的明确工程化偏离；不在 `agent-works` 复制第二份 SQL，避免双事实源，开发留痕与测试报告改为引用真实 migration。普通 seed 只能插入缺失稳定键，禁止使用 `ON CONFLICT ... DO UPDATE` 覆盖管理员或用户维护值；特殊数据修正必须使用独立 Flyway 版本、精确旧身份/旧值条件、影响计数校验和回滚/forward-fix 说明。菜单采用前端路由和服务端角色授权，无数据库菜单 seed；权限采用代码枚举和 Spring Security，不新增可漂移的权限配置表。第一期没有地图、币种、预算、账户余额或转账配置。

- 兄弟项目的桌面表格、动态布局和通用平台能力成熟但不等于适合本项目；若开发时直接复制，最容易破坏 P1-P5 手机信息顺序、触摸入口和低成本边界，必须按本计划的适配/排除清单审查。
- 复杂报表、全局搜索和多维下钻可能成为 PostgreSQL 热点；首期以索引和参数化聚合验证，不提前引入缓存。
- 浏览器 PWA 安装能力差异较大；安装属于渐进增强，网页功能不可依赖安装事件。
- 单机低成本部署降低运维成本但存在主机级故障域；R55 当前按用户要求只做同机副本，恢复演练仍是上线必要条件，但无法抵御整机/磁盘损坏。
- 注销在线删除与 180 天匿名审计策略已确认并解除 T19 阻塞；备份恢复重放及目标机隔离业务恢复已通过，主机/容器残余风险按本次内网例外登记。数据质量阈值已在 T22 确认并以 `expense-quality-v1` 落地，不再构成阻塞。

### 11.2 假设

- 技术基线已由用户确认；采用 Java LTS 和实施时受支持的 Spring Boot 稳定版本，精确小版本在 T1 锁定。
- 第一阶段是单区域、少量用户、单应用实例起步，但数据库幂等、任务租约和会话设计不依赖进程内状态，为后续扩容保留路径。
- 除已确认的收入分类候选外，原型中的“餐饮、交通、微信、商超”等仅为演示数据，不直接进入生产 seed。
- 备注500 Unicode code point、用户名3–64位可见ASCII已由接口校验固化；后续改变须同步契约与测试。
- 数据质量阈值以服务端常量和响应中的 `expense-quality-v1` 版本说明实现；具体值已在 T22 开始前确认，后续改变规则必须升级版本并同步测试与文档。
