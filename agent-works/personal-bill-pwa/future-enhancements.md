# 个人账单 PWA 后期增强说明

## 1. 文档职责

本文记录已明确不进入第一期、但需要保留产品演进边界的增强能力。它不是第一期验收清单；任何增强项进入开发前，仍需补齐业务闭环、成本评估、隐私说明、原子需求和独立验收。

## 2. R57 精准定位与地图选点

### 2.1 第一期边界

- 账单仅保存“未指定”或当前租户维护的常用地点文本标签。
- 第一阶段不请求浏览器定位权限，不接入地图 SDK，不存储经纬度、地址编码或地图服务商标识。
- 第一阶段填报、明细和报表不得展示不可用的“自动定位”或“地图选点”占位按钮。

### 2.2 建议触发条件

同时满足以下条件后再立项：

- 文本地点标签不能满足用户真实分析需求，并有明确使用数据或访谈证据。
- 已确定中国大陆访问可用、成本可控的地图服务及配额告警方案。
- 已完成定位用途、授权时机、保留期限、导出和删除的隐私说明。
- 精准位置带来的分析价值高于 SDK、合规、故障降级和数据保护成本。

### 2.3 推荐技术与数据边界

- 中国大陆场景优先评估高德地图 JavaScript API 2.0，坐标统一使用 GCJ-02；开发前须重新核验届时服务条款、价格和浏览器兼容性。
- 仅在用户主动点击“获取当前位置”或“地图选点”后请求权限，不在页面加载时自动请求。
- 常用地点保存用户自定义展示名、GCJ-02 坐标、地址摘要、来源类型、地图服务商和解析版本；不得只保存无法解释的地址字符串。
- 精确坐标属于敏感业务数据，必须租户隔离、受控导出和删除；管理端、普通日志、分析埋点和错误上报不得记录精确坐标。
- 第三方地图调用必须有超时、配额、熔断和错误归类，避免重复逆地理编码。

### 2.4 用户闭环

1. 用户主动选择“获取当前位置”或“地图选点”。
2. 系统在首次请求前说明用途；用户拒绝时保留原表单并继续使用“未指定”或文本标签。
3. 获取或选点成功后展示可确认的地址摘要，不自动保存账单。
4. 用户可改写常用地点名称，并明确选择是否保存为字典项。
5. 保存账单时记录位置快照和字典引用；后续字典改名不改变历史地址快照。
6. 用户编辑账单、导出数据或注销时，精准位置遵循与账单相同的权限和生命周期。

### 2.5 失败与降级

- 拒绝授权、系统定位关闭、超时、精度不足、SDK 加载失败、配额耗尽或逆地理编码失败均不得清空其他已填字段。
- 失败后允许改用文本地点标签或“未指定”；重复重试需要节流。
- 地图不可用时不展示假地图或伪造地址，明确说明失败原因和可继续路径。

### 2.6 进入开发前最低验收

- 授权同意、拒绝、撤回、系统定位关闭和超时均有可恢复路径。
- 地图选点、当前位置、手动改名、保存为常用地点、编辑和报表下钻形成闭环。
- 坐标系、地图服务商和解析版本可追溯，不发生坐标混用。
- 跨租户访问、管理员访问、日志泄露和导出越权负例均失败。
- 白天、夜晚、390px 手机视口、弱网和第三方服务不可用场景通过验证。

## 3. 其他后续能力索引

CSV 历史导入、票据 OCR、预算提醒、周期模板、家庭共享、支付账单文件导入和多商品消费批次仍按 [requirement.md](requirement.md) §5.2 管理。它们进入开发前应各自形成独立闭环，不与 R57 捆绑验收。
