# 个人账单 PWA 需求复核与整改报告

## 1. 结论

本轮针对“原型行为与正式需求不一致、上一版整改报告结论失真”的复核意见，重新检查了六个页面原型、共享脚本和样式，并扩大检查到同类筛选、异步任务、动态列表项、认证反馈、触控尺寸和运行错误。

整改后结论：**本轮复核指出的 5 项 P1、2 项 P2 均已关闭；结合此前已关闭的需求门禁，当前可以进入开发计划。** 该结论仅代表需求与交互原型达到计划输入条件，不代表原型替代真实后端实现或验收。

## 2. 已确认的需求门禁

以下决策已经同步在 `requirement-closure.md` 和 `requirement.md` 中，本轮未改变其口径：

| 决策 | 已确认口径 |
| --- | --- |
| B6 分类结构 | 最多两级；一级必填、二级选填 |
| B7 购买渠道 | 选填，默认展示“未指定” |
| B8 货币与时区 | 第一期仅人民币，业务时区为 `Asia/Shanghai` |
| B9 调整生命周期 | 支持未关联调整；关联调整随原支出冻结、恢复或联动永久删除，不保留孤立调整 |

第一期仍为 55 项必须需求，验收矩阵覆盖 R1-R71 中所有第一期项；必须、建议和暂不实现的范围划分没有变化。

## 3. 本轮审查意见与整改结果

| 审查意见 | 复核结论 | 实际整改 |
| --- | --- | --- |
| 报表筛选、范围和下钻上下文不一致 | 成立 | 筛选摘要只读取当前范围可见且启用的字段；内部值统一转为中文标签；应用收支范围时同步刷新页面标题和数据；时间范围使用选项真实起止日期；下钻携带当前 scope、range、维度、筛选值和滚动位置 |
| 调整操作会改错记录，生命周期变化不可观察 | 成立 | 每条调整绑定稳定 ID 和当前详情上下文；撤销只作用于当前行；新建未关联调整会新增列表项；原支出恢复会让关联调整恢复生效；联动永久删除同时移除原支出和关联调整 |

| 新增字典项不能继续维护 | 成立 | 初始项与动态新增项复用同一行工厂和事件绑定，新增后仍支持改名、排序、停用及恢复 |
| 整改报告与当前事实冲突 | 成立 | 删除未经本轮验证的“全部关闭”旧证据，以本轮静态检查和浏览器实测结果重写本报告 |

## 4. 举一反三检查与修复

- 报表筛选不只修复收入分类：所有筛选字段统一通过可见性、禁用态和业务范围判断，避免隐藏控件再次污染摘要或下钻参数。
- 导出不只修复一个入口：明细当前结果和个人全部数据使用同一任务状态模型，统一处理防重复、取消、失败、重试和下载结果。
- 调整不只修复撤销：新增、关联、转收入、冻结、恢复和联动永久删除都绑定当前记录，避免详情抽屉复用时串行。
- 字典不只为“付款方”打补丁：八类字典的初始项和新增项都走同一可维护组件逻辑。
- 管理端不只移除提示：检索、创建、刷新和详情均提供可验证的局部状态变化，避免正式按钮只显示 toast。
- 检查动态资源生命周期：重复生成 CSV 前撤销旧对象 URL，避免多次操作产生不必要的内存占用。

## 6. 验证记录

静态检查：

- `prototype.js` 通过 JavaScript 语法检查，Git diff 通过 whitespace 检查。
- 六个 HTML 的本地文件引用、重复 ID 和关键正式交互锚点完成检查。
- 检查正式业务按钮的 `data-toast` 残留；管理、调整、导出和字典变更均不再使用 toast 代替状态变化。
- 需求编号复核确认第一期必须需求仍为 55 项，正式需求与 DESIGN 不受本轮行为修复影响。

浏览器实测：

- 报表在“支出”页面选择“收入 + 今年 + 工资”后，页面切换为收入趋势，摘要显示中文业务值且不包含隐藏的支出字段；下钻范围为 `2026-01-01/2026-12-31` 并保留完整返回上下文。
- 新增未关联调整后有效列表数量增加；撤销“平台退款”不会删除“早餐包部分退款”；恢复“旧雨伞”后关联调整重新生效；联动永久删除后两条记录同时消失。
- 登录空值、错误凭据、网络失败、停用账号均在表单区反馈；临时密码能进入首次改密，短密码被拒绝，15 位以上一致密码能完成流程；个人修改密码同样拒绝短密码。
- 管理端无结果检索显示空态，重复用户名被拒绝，新用户创建后表格新增一行；运行概况刷新、日志刷新和日志详情均产生局部可见变化。
- 新增付款方后，新行仍具备改名、移动、停用和恢复能力。
- 两类导出在准备中禁用入口并显示取消按钮；取消、失败重试均有效；成功后分别生成 `当前筛选收支.csv` 和 `我的全部收支.csv` 的 Blob 下载链接。
- 六页在 `360×800` 下均无横向溢出，可见按钮、链接和表单控件均达到 44×44px；管理端在 `1366×900` 下无横向溢出；六页控制台无 JavaScript 错误。

## 7. 原型边界

- CSV 下载已验证生成真实 Blob URL、文件名和可点击下载链接；浏览器测试容器未提供系统下载目录结果，本轮不把“文件已落盘”列为已验证事实。
- 原型只验证交互与需求口径。真实实现仍需覆盖服务端租户隔离、鉴权、事务并发、审计不可抵赖、导出大数据量和回收站定时清理。
- 精准坐标、地图、账户余额和自有账户转账仍属于后期增强，需要独立立项和隐私评估。
