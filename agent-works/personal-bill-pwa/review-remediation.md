# 个人账单 PWA 全量复核与整改报告

## 1. 结论

本轮复核确认审查者指出的 7 项 P1、3 项 P2 均有事实依据，已完成实现、文档和测试同步。整改后重新检查全部 56 项一期必须需求、六页原型、共享样式、DESIGN 契约、前置闭环和建议开发顺序，未发现仍阻塞开发计划的 P0/P1 问题。

当前结论：需求与原型可以进入开发计划。这里的“通过”只表示需求原型形成可验证闭环，不等同于正式业务前端、后端接口、数据库隔离、Service Worker 或生产部署已经完成。

后续界面校准已同步：明细在支出或收入单一页签隐藏重复类型标签，在其他页签统一使用描边类型标签；“管理个人字典”已并入“数据与安全”，退出登录与注销账号已移至独立居中的“账号操作”分组。该调整未改变业务范围、编号或开发顺序。

## 2. 本轮整改

### 2.1 统一账目状态源

- 支出、收入、退款/报销调整统一使用带稳定记录 ID 的会话账目状态，不再由明细、报表和导出分别读取固定示例。
- 新增账目会进入状态源并在明细页生成真实记录；编辑收入或支出会更新原记录，列表金额、字段摘要、净支出和报表汇总同步变化。
- 明细组合筛选同时消费日期、账目类型、关键词和稳定资金渠道 ID；顶部类型分段控件与筛选抽屉使用同一已应用状态，无匹配时显示真实空态。
- 报表金额摘要、图表和排行由同一已应用条件及账目集合计算；支出调整继承原支出的资金渠道，待归类、冻结和回收站记录不进入正式统计。

### 2.2 导出和生命周期

- “导出当前结果”读取明细已应用条件；空结果不创建文件。“导出我的数据”覆盖有效和回收站中的个人收支及调整记录。
- CSV 统一包含记录 ID、账目类型、调整类型、关联账目 ID、状态、业务时间、收支完整字段、资金渠道、备注和生命周期，两个入口不再导出同一固定样本。
- 举一反三自审补充了输入输出安全边界：用户业务文本进入图表前统一 HTML 编码，CSV 对 `= + - @` 起始单元格做公式注入保护。
- 有效收入、支出和调整均有“移入回收站”入口；软删除后提供即时撤销。删除原支出会冻结并移动有效关联调整，恢复和撤销会同步重新生效。
- 回收站状态跨刷新保留；恢复、普通永久删除以及“连同关联调整永久删除”均改变实际状态，不遗留孤立调整。
- 关联及未关联调整表单均补充备注；调整详情展示备注，并支持撤销和软删除。

### 2.3 权限、PWA、响应式与可访问性

- permission 状态隐藏整个业务或管理 Shell；管理端侧栏、顶栏和模块导航不会在无权限页残留，只保留独立说明和安全返回登录入口。
- 登录页和“我的”复用同一个 PWA 安装组件：检测中显示 loading；收到浏览器 `beforeinstallprompt` 时才显示真实安装动作；不支持、拒绝/失败和已安装分别显示对应状态，不保留“知道了”式假安装按钮。
- 资金渠道、购买渠道和地点等业务候选改为自然换行，不再通过隐藏滚动条把选项放到屏幕外；短动作按钮仍保持单行。
- 普通字段在运行时补齐 `label[for] + control[id]`，芯片组使用 `aria-labelledby`；动态调整字段使用不会冲突的 ID。管理搜索和状态筛选补充可访问名称。

### 2.4 文档事实源

- `requirement.md` §12.2 成为非阻塞校准项唯一事实源，§2.3 只保留引用，不再维护第二份清单。
- `requirement-closure.md` 删除“实付金额可覆盖仍待确认”的过时表述，并把“进入正式需求阶段”改为当前开发计划门禁。
- “我的”页面重新承接 PWA 安装帮助，正式需求 P5-F4、页面原型和 DESIGN 组件登记保持一致。
- DESIGN 补充业务候选自然换行、表单可访问名称和 `PwaInstallPrompt` 复用契约；既有 Apple 风格、Action Blue、收入红色和支出绿色稳定契约未改变。

## 4. 浏览器动态回归

本轮通过本地 HTTP 服务重新执行浏览器回归，不沿用历史报告结论：

- 明细应用“收入 + 银行卡 + 不存在的关键字”后，摘要、顶部收入类型、可见记录数 0 和空态一致。
- 早餐包实付从 `28.00` 改为 `20.00` 后，列表显示 `−¥20.00`、净支出 `¥10.00`；进入报表后原始支出、冲减、净支出和结余同步重算。
- 报表应用“支出 + 不存在的关键字”后，摘要保持中文业务语义，金额归零，图表与排行隐藏并显示无数据状态。
- 从记账页新增“矿泉水”后，明细页新增第六条有效记录并完整展示单位、数量、单价、资金渠道和金额。
- 软删除支出后原记录和关联调整从有效列表消失，回收站数量增加；即时撤销后两者恢复。新增账目删除并刷新后，回收站仍提供恢复和永久删除操作。
- 空筛选结果导出不会生成 Blob 下载，页面明确提示“未生成文件”；完整个人数据导出生成隐藏 Blob 下载，文件名为“我的全部收支.csv”。
- `admin-console.html?state=permission` 下管理 Shell 和管理导航均不可见，独立无权限说明和返回登录入口可见。
- PWA 入口先显示检测状态；当前不支持直接安装的浏览器随后只显示平台操作步骤，页面不存在“知道了”假按钮。
- 六页 `360×800` 均无整页横向溢出、无小于 `44×44px` 的可见交互控件；存在业务候选的页面计算样式为 `flex-wrap: wrap`。管理端 `1366×900` 已重新实测，无横向溢出、过小控件或无名表单字段。
- 后续界面校准在 `390×844` 复验：全部、调整和回收站中的账目类型均显示同一描边标签，支出与收入单一页签隐藏重复标签；“数据与安全”包含唯一个人字典入口，“账号操作”中的退出与注销在白天、夜晚均居中，54px 行高且无横向溢出。
- 六页控制台错误与警告为 0；动态字段无重复 ID，全部 `input/select/textarea` 具有可访问名称。

## 5. 全量复核边界

- 角色、权限、B1-B9、收入与支出口径、56 项一期范围、验收矩阵和开发阶段依赖未发生非授权扩张。
- 本轮没有新增业务确认项；调整内容均可由现有稳定记录 ID、生命周期、页面状态和 DESIGN 契约直接推出。
- 正式开发仍需把原型会话状态替换为服务端接口与数据库事务，并落实租户隔离、幂等键、版本冲突、异步导出、RLS、备份恢复和生产 PWA 安装验证；这些属于既有开发范围，不是本轮原型缺口。
