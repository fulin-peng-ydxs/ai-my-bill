# 个人账单 PWA 需求复核与整改报告

## 1. 本轮结论

本轮复核实现提交 `5abc080` 和报告提交 `f46dd9e`。审查新指出的 1 项 P1、2 项 P2 均成立；问题属于既有 R19、P5-F1 和页面语义的原型承载遗漏，不涉及新增业务决策。

本轮已补齐统一偏好状态源、保存与消费闭环、失败重试、安全回退、恢复默认和最近记账类型同步，并修正注销反馈与原型说明转义。随后重新检查了正式需求、前置闭环、范围编号、验收追溯、开发顺序、六页原型、DESIGN 契约和确认项边界。静态检查及真实浏览器动态回归均通过，当前需求与原型具备进入开发计划的条件。该结论只表示计划输入完整，不把原型行为等同于生产系统验收。

- 第一期仍为 55 项必须需求，编号唯一且均进入验收矩阵。
- 必须、建议、暂不实现及建议开发顺序没有变化。
- `requirement.md` 已在 R19、P5-F1 和验收矩阵中明确偏好的定义、保存、消费、失败回退、非法值处理和恢复默认；`DESIGN.md` 已规定配置项的来源、持久化、消费、回退和验证契约。本轮只修复原型承载，因此 `requirement.md`、`requirement-closure.md` 和 `DESIGN.md` 无需修改。

## 4. 举一反三与复用检查

- 检查了所有偏好消费者，而非只修个人页文案：支出支付方式、收入收款方式、最近记账类型、明细默认范围、报表默认范围、主题初始化及清除临时筛选均使用统一状态。
- 区分“持久化成功值”和“本会话待重试值”。额外修复了一个审查未指出的问题：一项保存失败后，保存另一项不会把前一项待重试值误写入持久化状态。
- 主题控件选择器限定为真实按钮，避免页面根节点因同名状态属性被误绑点击事件；主题也复用统一偏好异步保存函数，不再维护第二套提交逻辑。
- 默认资金渠道的候选值在支出和收入表单中保持一致；非法、停用或未知枚举统一回退到安全默认值。
- 明细和报表的临时筛选可覆盖个人默认，但执行“清除”时恢复各自默认范围，不互相污染。
- 报表时间范围不仅更新筛选摘要，还同步页头周期、结余卡名称、下钻值和排行标题，避免“今年”范围仍显示“本月结余/本月构成”的矛盾口径。
- 复用了既有 `setButtonLoading`、chip、overlay、dialog、状态块和主题缓存；新增的规范化、读取、会话暂存、持久化和异步保存函数由全部偏好共用。明细与报表共用一个范围设置抽屉，资金渠道因输入形态不同保留独立选择区域。
- 全项目原型说明中继续检索裸 `&region=` 和 `®ion=`，未发现其他同类错误。

- 偏好状态复用检查确认：全部保存入口消费同一异步提交函数，全部页面消费者读取同一规范化状态源。

### 6.2 浏览器动态回归

- 默认资金渠道选择“支付宝”时，保存按钮进入禁用和“保存中”；`?preference=error` 首次失败后选择与个人页“待重试”状态保留，再次提交成功并回显“支付宝 · 修改”。
- 保存成功后，记账页支出支付方式和收入收款方式均默认选中支付宝。
- 最近记账类型切换为收入或支出后，个人页分别显示“收入 · 自动保存”或“支出 · 自动保存”。
- 明细默认范围保存为“上月”、报表默认范围保存为“今年”后，对应页面摘要及筛选控件真实消费；临时改为其他范围后执行“清除”，分别恢复“上月”和“今年”。
- 报表使用“今年”默认范围时，页头显示“今年 · 2026年”，总览卡显示“今年结余”，排行显示“今年收支构成”，结余下钻值同步为“今年结余”。
- `?preference=invalid` 模拟非法或停用值时，资金渠道回退微信、记账类型回退支出、明细和报表范围回退本月、主题回退跟随系统。
- “恢复默认偏好”提交期间按钮禁用；成功后资金渠道、两个范围、最近记账类型和主题全部恢复默认并回显。
- 主题保存支持提交中、防重复、一次失败后保留当前主题并重试；成功后跨页保持夜晚模式。
- `login.html?reason=account-cancelled` 显示中性“会话状态 / 账号已进入注销处理”，不显示“登录失败”。
- 个人页和管理端状态验证说明均实际显示 `&region=`，未出现 `®ion=`。
- 六页在 `360×800` 下均为 `scrollWidth=clientWidth=360`，可见交互控件无小于 44×44px 项，页面控制台错误均为 0；管理端在 `1366×900` 下 `scrollWidth=clientWidth=1366`，控制台错误为 0。

## 7. 动态验证边界

- 浏览器测试通过本地 HTTP 服务运行，不再存在“无法启动服务或无法访问本地页面”的限制。
- 查询参数只用于模拟一次失败、非法值等代表性状态；生产实现仍须用真实接口、服务端校验、事务、租户隔离和并发测试验收。
- 原型的浏览器存储用于证明设置—消费链路；生产偏好应按正式需求由服务端作为权威来源，本地仅用于安全缓存和本会话失败保留。

## 8. 原型边界

- 原型异步保存以定时器和故障参数演示 loading、失败及重试；生产实现必须处理超时、幂等、版本冲突和服务端非法值。
- 原型内的安全默认只代表已确认业务默认；生产系统读取停用字典项时还需由服务端返回可用候选并记录回退原因。
- 本轮整改只修复原型和整改记录，不把原型演示行为等同于生产系统验收。
