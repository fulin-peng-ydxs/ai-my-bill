# 个人账单 PWA 需求复核与整改报告

## 1. 结论

本轮对上游闭环、正式需求、DESIGN、六个页面原型和共享样式/脚本进行了全量复核，不只复查原审查者列出的行。

整改后的结论仍为：**暂不进入完整开发计划**。文档结构、编号、页面闭环和原型承载已达到继续确认需求的条件，但 B1-B5 尚未获得用户确认，分别阻塞认证、商品唯一判定、精度、账单生命周期和地图位置模块。关闭阻塞项并同步文档后，需再做一次全量复核。

## 3. 全量复核新增发现

### 3.1 需求与来源

- 位置、购买渠道和常用地点并非用户原始核心字段，属于闭环阶段推断扩展；正式需求原先标为“用户补充”不准确，现已校正来源。
- 登录原型和管理端曾把一次性凭据、首次改密当成既定流程，和 B1 冲突；现改为中性“账号标识/认证凭据”承载，不宣称最终机制。
- 原型和需求中 `30 天`、三位数量精度、完整商品规范化算法均已移除，避免继续污染实体和验收。

### 3.2 DESIGN 与实现

- DESIGN 遮罩色仍残留旧绿色主题的 `rgba(8,20,20,.38)`，而当前主题已是靛蓝/铜橙；已改为中性靛蓝黑遮罩并同步原型 token。
- 共享 CSS 的主题切换选中阴影仍带旧绿色值，主按钮前景色也绕过语义 token；已新增 `on-primary` 与控件阴影 token 并统一消费。
- `theme-color` 与首屏同步脚本必须在 CSS 生效前工作，DESIGN 原先“禁止硬编码”缺少此机器产物例外；已明确这些值必须由主题 token 生成，不能成为第二套事实源。

### 3.3 页面与复用

- 原型六页都复用同一个主题、状态、弹层、金额、筛选和图标脚本；第二次出现的交互没有继续复制页面私有实现。
- “我的”六类字典不再打开固定商品列表，而是按入口切换对应标题与演示数据。
- 六页统一支持查询参数状态承载；登录等没有集合数据的页面不制造假业务空态，empty 只验收其独立数据区域。
