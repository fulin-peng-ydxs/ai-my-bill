# 个人账单 PWA 需求复核与整改报告

## 1. 本轮结论

本轮以提交 `bfeb9ed` 为复核基线。审查新指出的 1 项 P1 成立：资金渠道虽然已经统一消费同一字典，但原型仍以名称同时承担展示文案和业务标识，导致用户渠道可与筛选占位及管理操作共享同一值或同一可见语义。

本轮已将资金渠道改为稳定 ID 引用，名称仅用于展示；筛选占位使用保留内部哨兵值，渠道候选和管理操作使用可区分的显示与无障碍语义。重新检查正式需求、前置闭环、范围编号、验收追溯、开发顺序、六页原型、DESIGN 契约及确认项边界后，静态检查和真实浏览器动态回归通过，1 项 P1 已关闭，当前需求与原型具备进入开发计划的条件。该结论只表示计划输入完整，不把原型行为等同于生产系统验收。

## 2. 需求事实与同步判断

- B1-B9、角色、权限和租户边界继续有效，没有新增业务确认项。
- 第一期仍为 55 项必须需求，编号唯一且均进入验收矩阵。
- 必须、建议、暂不实现及建议开发顺序没有变化。
- `requirement.md` 的 R19、R41、R56 和 P5-F1 已明确失败会话值、完整资金渠道复用和统一筛选；但复核发现审查意见所称的“现有稳定字典 ID 契约”此前并未在正式需求中显式出现。本轮已在 §7 补充稳定 ID、展示名称和筛选哨兵值的边界，并在 §10 增加与筛选占位、管理操作同名的验收用例。该补充不改变需求编号或一期范围；`requirement-closure.md` 和 `DESIGN.md` 的既有范围及稳定设计契约无需修改。

## 4. 举一反三与复用检查

- 检查了资金渠道全部消费者：默认资金渠道、支出支付方式、收入收款方式、支出/收入编辑、明细筛选、报表筛选及个人字典维护；候选均传递稳定 ID，不再以显示名称充当业务值。
- 报表和明细的资金渠道 `select` 共用同一渲染函数；支出、收入和个人偏好的 chip 也由同一启用项列表生成，操作入口统一为“管理资金渠道”。
- 字典新增后所有消费页立即出现；停用后从所有新填报和筛选候选退出；恢复后重新出现。当前默认被停用时，已保存值和待重试值均不会复活为非法候选。
- 字典改名不再迁移引用，只更新稳定 ID 对应的展示名称；重复、空名称和停用最后一个启用项会被拒绝。
- 旧版偏好或待重试会话中的名称引用在读取时立即解析并写回稳定 ID，避免用户先改名时丢失历史默认值或待重试状态。
- 举一反三覆盖“全部渠道”“管理”“管理资金渠道”三个边界名称：筛选占位、真实渠道与管理操作的值、显示或无障碍语义均可区分；保留哨兵值不能作为字典 ID。
- 额外清除了 HTML 中重复维护的静态资金渠道选项，避免源代码与运行时事实源再次分叉。
- 偏好提交继续复用统一 `savePreference`、按钮 loading、overlay、状态块和主题缓存；资金渠道维护继续复用现有字典行工厂、排序和停用控件，没有新增平行组件。

### 6.2 浏览器动态回归

- 新增“全部渠道”“管理”“管理资金渠道”后字典计数由 4 变为 7；重复新增“全部渠道”被拒绝且计数保持 7。
- 报表筛选同时显示占位“全部渠道”和真实项“全部渠道（资金渠道）”；前者值为 `__all_funding_channels__`，后者为独立 `funding-*` ID。选择真实项后摘要明确显示“全部渠道（资金渠道）”。
- 记账页把真实渠道“管理资金渠道”显示为“管理资金渠道（渠道）”，无障碍名称为“选择资金渠道：管理资金渠道”；操作入口显示及无障碍名称均为“管理资金渠道”。“管理”渠道也与操作入口保持区分。
- 将默认资金渠道设置为动态项“管理”后改名为“管理渠道”，个人页立即回显“管理渠道 · 修改”，证明偏好继续引用同一稳定 ID，而非依赖旧名称。
- 旧版名称型字典和偏好数据加载后自动迁移为 ID；空名、重复名称、重复或保留 ID 会被规范化，非法或全停用字典继续回退默认四项。
- 六页在 `360×800` 下均为 `scrollWidth=clientWidth=360`，可见交互控件无小于 44×44px 项，控制台错误均为 0；管理端在 `1366×900` 下 `scrollWidth=clientWidth=1366`，控制台错误为 0。

## 7. 动态验证边界

- 浏览器测试通过本地 HTTP 服务运行，不存在本地服务或页面访问限制。
- 原型使用浏览器存储模拟服务端个人偏好和字典，查询参数只用于模拟一次失败与非法数据；生产实现必须由服务端按租户返回稳定 ID 和展示名称，并处理版本冲突和并发停用。
- 原型已使用稳定字典 ID 证明改名不改变引用；生产账单还应保留名称快照，用于历史展示和审计。

## 8. 原型边界

- 原型的逐字段状态用于证明页面不会把待重试值伪装成已保存；生产接口还须返回字段级版本或整体偏好版本，并对重试使用幂等语义。
- 原型停用后立即从新操作候选退出；生产实现还须保证服务端校验已停用 ID，不能只依赖前端隐藏。
- 本轮只修复原型和整改记录，不把原型演示行为等同于生产系统验收。
