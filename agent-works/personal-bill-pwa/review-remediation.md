# 个人账单 PWA 需求复核与整改报告

## 1. 本轮结论

本轮以用户确认的最新视觉与交互契约为准，保留 Action Blue 操作体系、收入红/支出绿业务语义、报表页签切换、图表下钻和现有页面承载关系。除前述颜色、表单分组和交互层级整改外，最新反馈要求金额摘要不再为结余单独留出空列，并以“日常支出/日常收入”替换“复制上一笔”，让有效账目能够沉淀为可复用填报模板。

现已完成任务优先重构，并新增日常收支模板闭环：有效支出/收入可从列表收藏图标或编辑抽屉页头的同源图标加入，同类型按规范化名称唯一更新；记账页按当前类型选择模板回填，时间更新为现在、备注不复制，保存前继续执行普通字段治理。金额摘要改为两列自然流，只有奇数末项通栏。移动端业务长内容改为自然换行，返回类按钮保持单行；退出登录使用 Action Blue，注销继续使用危险色。上述规则均进入机器可执行的设计契约测试。

本轮进一步收敛低频动作层级：退出登录所在设置行统一移除链接下划线；“导出当前结果”从账单流末尾移到收支明细页头，使用带可访问名称的 44×44px 下载图标。处理中同一图标原位切换为取消，完成后直接触发 CSV 下载并恢复，不再向页头追加“取消导出”或“下载 CSV”文字按钮；失败仍保留当前条件并可重试。

## 2. 最新颜色契约

- Action Blue 继续作为唯一普通操作色：白天 `#0066CC`，夜晚 `#2997FF`。
- 收入图表和非文字强调固定使用 `#FF3B30`，支出固定使用 `#34C759`，两种主题不换色。
- 收入文字使用白天 `#D70015`、夜晚 `#FF6961`；支出文字使用白天 `#188038`、夜晚 `#34C759`。
- 次要文字使用白天 `#6E6E73`、夜晚 `#CCCCCC`；placeholder 夜晚使用 `#A1A1A6`。
- 成功、警告、危险状态使用独立主题前景 token，不再直接复用不满足文字对比度的图表强调色。
- 夜晚主按钮使用黑字配 `#2997FF`；禁用按钮使用白字配 `#6E6E73`。
- 图表仍保留原红绿填充；若填充与表面对比度不足，使用可读文字色轮廓，并继续通过标签、数值和位置传达含义。

## 3. 需求与文档同步

- `requirement.md`、`requirement-closure.md` 和 `DESIGN.md` 已统一颜色、交互层级、金额摘要排布和日常收支模板契约。
- 本轮没有新增页面、角色或权限；新增 R72 日常收支快捷模板，并明确替代 R6 原“复制上一笔”子能力。R6 的保存并继续与最近使用语义不变。
- 第一期现为 56 项必须需求：既有编号保持稳定，新增 R72；验收矩阵缺失 0 项。
- 必须实现新增 R72；R28 周期性收支仍为后续建议，二者不会混用。建议开发顺序把 R72 放在明细与填报数据稳定阶段完成。
- 六个既有 HTML 原型继续承载全部页面范围，不需要新增原型文件。
- `DESIGN.md` 已登记 `AppliedFilterBar`、`SegmentedControl`、`SettingsDisclosureList`、`DailyEntryPicker` 和 `DailyEntryFavoriteAction`，并明确报表、列表、设置页和模板字段治理规则。

## 4. 实现与复用判断

- 所有颜色继续由 `prototype.css` 根级主题 token 统一管理，没有新增页面私有色值或平行主题实现。
- 收支页签、金额、标签和状态统一消费文字前景 token；报表图形统一消费强调色 token。
- 图表、明细、记账和设置页共享同一套语义 token，名称与职责按同一变化原因拆分，不在页面内重复定义。
- 对比度计算直接进入既有 `design-contract.test.mjs`，没有为单页创建重复测试脚本。
- 新增与编辑两条链路统一复用 `entry-form`、`form-section`、`form-section-head`、`form-section-title` 和 `form-section-note`，没有形成页面或场景私有样式。
- 支出按“商品信息、金额信息、渠道与场景、时间与备注”分为四组；收入按“收入信息、金额与收款、时间与备注”分为三组。字段、控件 ID、校验、草稿和提交流程均未改变；明细页两个编辑抽屉已同步分组，避免新增和编辑体验分叉。
- 支付/收款方式候选区仅渲染真实资金渠道，“管理”作为字段标题侧独立动作；购买渠道和地点标签沿用同一规则，避免操作按钮伪装成业务选项。
- 报表和明细复用 `filter-summary` 作为已应用条件与唯一筛选入口；抽屉草稿仍与已应用状态隔离，取消不污染图表或列表。
- 报表范围与明细类型/生命周期复用 `segmented-control`；超过三个的报表分析维度改为选择器，不再横向滚动大量胶囊。
- 设置首页复用 disclosure 列表表达“分类 + 当前值 + 下级入口”，八类字典先进入索引抽屉，再进入真实维护抽屉。
- 六页已移除只用于审查说明的 `prototype-note`；权限、失败、隐私边界等真实业务提示继续保留为页面状态或说明。
- 金额摘要统一使用两列自然流选择器，奇数末项通栏；不再通过单项专有跨列规则制造空位。
- 日常模板的名称规范化、同键更新、字段快照白名单和失效资金渠道回退集中在 `prototype.js`，填报页与明细页不各自复制规则；列表结构复用 `daily-template-*` 样式。
- 账单列表收藏图标与编辑抽屉页头图标复用同一模板写入、状态刷新和无障碍命名逻辑；调整与回收站没有错误暴露收藏入口。
- 移动端标题、元信息、筛选和下钻上下文统一自然换行；按钮统一单行，避免把业务内容截断和把短动作挤成逐字换行。
- 设置链接统一由 `setting-row` 取消默认下划线；明细导出复用共享 `icon-btn` 和图标事实源，不新增单页按钮样式或第二套导出逻辑。
- 原型使用共享样式表达最低复用单元；正式前端实现时应按 `DESIGN.md` 落为共享 `FormSection` 组件。

## 6. 原型边界

- 当前验证对象仍是需求原型，不等同于正式业务前端验收。
- 正式实现必须沿用强调色与文字色分层，并把同等对比度断言迁移到正式主题 token 或视觉契约测试。
- 正式图表库接入后仍需验证 Canvas/SVG、tooltip、选中态和键盘焦点的实际对比度，不能只验证 CSS 变量。
