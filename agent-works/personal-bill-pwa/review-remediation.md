# 个人账单 PWA 需求复核与整改报告

## 1. 本轮结论

本轮以提交 `83569ee` 为复核基线。审查新指出的 2 项 P1 均成立：偏好状态虽然区分了已保存值与会话值，但没有逐字段保留错误状态；资金渠道候选仍由多个页面静态维护，没有形成可新增、停用和回退的统一事实源。

本轮已补齐逐字段 `saved / pending / error` 状态和统一启用资金渠道字典，并重新检查正式需求、前置闭环、范围编号、验收追溯、开发顺序、六页原型、DESIGN 契约及确认项边界。静态检查和真实浏览器动态回归通过，2 项 P1 已关闭，当前需求与原型具备进入开发计划的条件。该结论只表示计划输入完整，不把原型行为等同于生产系统验收。

- B1-B9、角色、权限和租户边界继续有效，没有新增业务确认项。
- 第一期仍为 55 项必须需求，编号唯一且均进入验收矩阵。
- 必须、建议、暂不实现及建议开发顺序没有变化。
- `requirement.md` 的 R19、R41、R56 和 P5-F1 已明确失败会话值、完整资金渠道复用和统一筛选；`DESIGN.md` 已明确配置项事实源、合法值域、真实消费、回退和测试。本轮问题是原型没有完整承载既有契约，因此 `requirement.md`、`requirement-closure.md` 和 `DESIGN.md` 无需修改。

## 4. 举一反三与复用检查

- 检查了资金渠道全部消费者：默认资金渠道、支出支付方式、收入收款方式、支出/收入编辑、明细筛选、报表筛选及个人字典维护，不再保留页面私有候选数组。
- 报表和明细的资金渠道 `select` 共用同一渲染函数；支出、收入和个人偏好的 chip 也由同一启用项列表生成，差异只保留“管理”入口。
- 字典新增后所有消费页立即出现；停用后从所有新填报和筛选候选退出；恢复后重新出现。当前默认被停用时，已保存值和待重试值均不会复活为非法候选。
- 字典改名同步迁移已保存或待重试的资金渠道引用；重复、空名称和停用最后一个启用项会被拒绝。
- 额外清除了 HTML 中重复维护的静态资金渠道选项，避免源代码与运行时事实源再次分叉。
- 偏好提交继续复用统一 `savePreference`、按钮 loading、overlay、状态块和主题缓存；资金渠道维护继续复用现有字典行工厂、排序和停用控件，没有新增平行组件。

### 6.2 浏览器动态回归

- 严格复跑审查链路：支付宝保存失败后显示“支付宝 · 待重试”；切换到无故障页面保存“报表默认范围=今年”成功，支付宝仍显示“待重试”；刷新个人页后状态不变；记账页支出和收入仍实际消费支付宝。
- 从个人页重新打开默认资金渠道时，失败提示和支付宝选中状态仍在；重试成功后才变为“支付宝 · 修改”。
- 新增启用“云闪付”后，字典计数由 4 变为 5；个人偏好、支出、收入、两类编辑抽屉、明细和报表同时出现该候选，并可作为两类记账默认值。
- 报表和明细筛选完整包含“微信、支付宝、银行卡、现金”及动态新增项；选择现金应用后摘要显示“今年 · 全部 · 现金”。
- 停用当前默认“云闪付”后，个人偏好安全回退微信；支出、收入和报表候选均移除云闪付；恢复后重新出现。
- `?funding=invalid` 模拟空名、停用和非法字典数据时，所有消费者回退为默认四个启用渠道。
- 六页在 `360×800` 下均为 `scrollWidth=clientWidth=360`，可见交互控件无小于 44×44px 项，控制台错误均为 0；管理端在 `1366×900` 下 `scrollWidth=clientWidth=1366`，控制台错误为 0。

## 7. 动态验证边界

- 浏览器测试通过本地 HTTP 服务运行，不存在本地服务或页面访问限制。
- 原型使用浏览器存储模拟服务端个人偏好和字典，查询参数只用于模拟一次失败与非法数据；生产实现必须由服务端按租户返回带稳定 ID 的启用字典项，并处理版本冲突和并发停用。
- 原型以名称模拟字典引用，已实现改名迁移用于证明闭环；生产数据应使用稳定字典 ID，历史账单继续保留名称快照。

## 8. 原型边界

- 原型的逐字段状态用于证明页面不会把待重试值伪装成已保存；生产接口还须返回字段级版本或整体偏好版本，并对重试使用幂等语义。
- 原型停用后立即从新操作候选退出；生产实现还须保证服务端校验已停用 ID，不能只依赖前端隐藏。
- 本轮只修复原型和整改记录，不把原型演示行为等同于生产系统验收。
