# 个人账单 PWA 正式需求文档

## 1. 文档状态与目标

本项目面向中国大陆个人和少量用户，建设一款手机优先、可互联网访问的个人账单 PWA。第一期聚焦两条主链路：低负担记录商品级消费，以及从多维报表追溯到原始账单。

当前状态为：**业务闭环与页面范围已形成，暂不具备直接生成完整开发计划的条件**。§3 的五项模块阻塞事项会改变认证流程、数据约束、生命周期或第三方集成，必须先确认。与这些事项无关的设计基座、原型和技术调研可以继续，但不能用临时默认值固化接口或数据库。

产品目标：

- 常见商品通过最近使用、默认值和连续录入快速保存。
- 商品、分类、单位、支付方式、购买渠道和常用地点随使用沉淀。
- 报表覆盖时间、分类、商品、支付方式、购买渠道、位置、习惯、价格、频次和数据质量，并可下钻到原始账单。
- 修改、删除或恢复账单后，明细与报表保持同一口径。
- 一个普通用户对应一个租户，任何访问路径均不得跨租户。
- 以低成本完成试用部署，并保留中国大陆稳定部署、备案和扩容路径。

### 2.1 项目事实

- 当前仓库只有需求、DESIGN 和静态交互原型，没有业务代码、数据库、接口、测试或部署配置。
- 上游闭环事实源为 [requirement-closure.md](requirement-closure.md)。

- 六个页面原型位于 [prototypes](prototypes/)，用于验证结构、交互和状态，不替代本文业务规则。

### 2.2 用户已明确确认

- 第一阶段一个普通用户对应一个独立租户，不支持家庭共享账本。
- 商品名称在当前租户的商品字典内唯一；同一商品可以形成多条消费记录。
- 第一阶段采用 PWA，主要服务中国大陆个人和少量用户。
- 主题必须支持白天与夜晚；DESIGN 进一步定义 `system/light/dark` 三种偏好。

## 4. 用户角色与权限

### 4.1 系统管理员

管理员维护普通用户、面向新用户的默认字典、运行概况和管理员操作日志。管理员默认不能查看、搜索、导出或修改用户消费明细；用户管理返回模型也不得包含商品、金额、位置等消费字段。

### 4.2 普通用户

普通用户只操作自己租户下的账单、商品、分类、单位、支付方式、购买渠道、常用地点、报表、偏好和导出任务。租户归属必须来自服务端身份上下文，客户端不得提交或切换资产租户标识。

### 4.3 固定入口

普通用户手机端底部导航固定为“记一笔、报表、明细、我的”。管理员登录后进入隔离的系统管理入口；普通用户直接访问管理页面或接口时显示无权限，不伪装成空数据。

## 6. 核心业务规则

### 6.1 填报字段与校验

| 字段 | 必填 | 已确定规则 | 待确认约束 |
| --- | --- | --- | --- |
| 消费时间 | 是 | 默认当前时间，不允许明显未来时间 | 默认时区候选为 `Asia/Shanghai` |
| 商品 | 是 | 选择已有或快捷新增；租户内唯一 | B2 名称规范化 |
| 分类 | 是 | 选择启用项，已有商品可带出 | 最大层级 |
| 单位 | 是 | 选择启用项，已有商品可带出 | 无 |
| 单位价格 | 是 | 值 `≥0`，使用十进制精确计算 | B3 小数位与上限 |
| 数量 | 是 | 默认 1，值 `>0`，允许小数 | B3 小数位与上限 |
| 计算金额 | 系统 | 单价 × 数量 | B3 舍入与展示精度 |
| 实付金额 | 是 | 默认等于计算金额，可由用户修改，值 `≥0` | B3 小数位与上限 |
| 支付方式 | 是 | 选择启用项，优先用户偏好或最近使用 | 无 |
| 购买渠道 | 待确认 | 候选为选填并允许“未指定” | 开发填报前确认 |
| 购买位置 | 否 | 未指定、常用地点、自动定位或地图选点 | B5 |
| 备注 | 否 | 去除首尾空格，长度上限需在接口契约中确定 | 最大长度 |

用户修改实付金额后，单价或数量变化不得静默覆盖；系统显示计算金额与实付金额差额。选择已有商品只带出默认值，不自动保存。保存并继续保留消费时间、支付方式、渠道和位置，清空商品相关字段；复制上一笔更新消费时间并要求用户再次确认。

### 6.2 商品与字典

- 商品唯一性是已确认规则，具体规范化算法由 B2 决定；未确认前原型只演示冲突流程，不给出算法结论。
- 分类、单位、支付方式、购买渠道和常用地点均支持新增、改名、排序、停用、恢复。
- 停用项不进入新填报默认候选，但历史账单继续显示原快照。
- 被历史账单引用的字典项不得物理删除。
- 商品合并前展示影响数量并二次确认；合并后更新统计归属、保留历史解释并记录去向。
- 系统默认字典只初始化新用户，随后形成个人副本；管理员修改不得覆盖存量用户。

### 6.3 明细、删除、导出与注销

- 明细按日期、商品、分类、支付方式、购买渠道、常用地点、金额范围和状态组合筛选，默认按消费时间、创建时间倒序稳定排列。
- 编辑复用填报全部字段和校验；若记录版本已变化，保留用户输入并提示刷新或重新确认。
- 软删除账单立即退出有效报表并提供撤销、回收站恢复；保留与永久清理期限由 B4 决定，原型不得写死天数。
- CSV 导出至少包含消费时间、商品、分类、单位、单价、数量、计算金额、实付金额、支付方式、购买渠道、购买位置、备注和状态，且只包含当前用户。
- 注销前建议导出并二次确认；注销使会话失效，数据删除或受控保留需满足正式运营隐私政策。

### 6.4 报表统一口径

- 金额统一使用实付金额；时间统一使用消费时间；只统计未删除账单。
- 每条账单是一条商品消费明细，数量指标称“消费明细数”，不得称“交易笔数”。
- 同一商品不同单位的数量和单价分别统计，不能直接相加；金额可汇总。
- “填写单价”和“实付金额 ÷ 数量”的“实际单位成本”必须分别命名。
- 同比无可比期、环比前期为零或数据不完整时显示不可计算及原因。
- 全局筛选支持时间、分类、商品、支付方式、购买渠道和常用地点；所有区域显示并消费同一摘要。
- 点击时间点、分类、商品、支付方式、渠道、地点或异常线索进入明细并携带可序列化上下文；返回恢复筛选、维度和滚动位置。

### 6.5 定位与位置隐私

- 定位和地图均为增强能力；拒绝授权、超时、地图不可用或逆地理编码失败时回到“未指定”，不得阻断账单保存。
- 坐标和常用地点属于当前租户敏感数据；日志不得记录精确坐标。
- B5 关闭前，原型只能演示“选择位置”的业务交互，不宣称具体地图、坐标或地址解析已可交付。

### 6.6 四态与动作反馈

- 页面及独立数据区采用互斥的 `ready/loading/empty/error`；无权限属于 error 变体，不是假空态。
- 首次加载不显示空态；已有数据刷新保留旧值并显示局部 loading。
- 空态解释为什么为空并提供下一步；普通错误提供重试；无权限不提供无意义重试。
- 保存、删除、导出等异步动作显示 loading、防重复触发；动作失败保留用户输入。
- 原型统一用查询参数 `?state=loading|empty|error|permission` 验证状态承载，`ready` 为默认；登录等没有集合数据的页面不强制制造业务空态，`empty` 只验收其独立数据区域。

| 用户 | 身份、状态、最近活跃 | 普通用户唯一归属一个租户；认证字段受 B1 阻塞 |
| 租户 | 标识、状态 | 第一阶段一用户一租户 |
| 商品 | 展示名、唯一判定键、分类、默认单位、最近值、状态 | 唯一键算法受 B2 阻塞 |
| 分类/单位/支付方式/购买渠道 | 名称、排序、状态 | 租户内维护，历史引用保护 |
| 常用地点 | 名称、位置数据、排序、状态 | 租户内维护；数据格式受 B5 阻塞 |
| 账单 | 消费字段、名称快照、关联、删除状态、版本 | 精度受 B3 阻塞；租户不可由客户端指定 |
| 用户偏好 | key、合法值、更新时间 | 服务端为登录态权威，本地仅安全回退 |
| 管理操作日志 | 管理员、动作、对象、结果、时间 | 不记录凭据、坐标和消费内容 |

- 所有业务接口从认证上下文确定用户和租户，不接受任意租户参数。
- 写接口提供字段校验、版本冲突和幂等结果；账单与最近使用信息保持一致。
- 修改、删除、恢复和商品合并后使相关报表缓存失效。
- 金额使用十进制精确类型；B3 未关闭前不固化 scale。
- 导出采用受控任务或流式响应，避免大数据一次性加载。
- 永久清理与注销采用可审计后台任务，不由前端直接批量物理删除。

## 8. 页面与逐功能交互闭环

以下六页均为新增页面。每个功能点均说明输入、校验、动作、状态、权限、刷新联动和验收；共同的视觉、四态、弹层、触控和响应式规则以 DESIGN 为事实源。

### 8.1 P1 登录与安装

- **入口/权限**：未登录访问应用或会话失效回跳；登录成功后按角色进入“记一笔”或系统管理。
- **原型**：[login.html](prototypes/login.html)；对应 R1、R2、R22、R54；认证实现受 B1 阻塞。

#### P1-F1 登录

- 输入账号标识与密码；账号标识的具体类型、格式、找回入口和首次认证方式等待 B1。
- 两字段为空时就地提示；提交期间按钮 loading 且禁止重复请求；取消不适用。
- 成功按角色跳转；凭据错误、账号停用、网络失败和系统失败在表单区反馈，不泄露账号是否存在。
- 会话失效返回本页；重试不清空账号字段；未登录用户可用，已登录用户进入对应首页。
- 验收：键盘回车可提交，失败可恢复，重复点击只产生一次请求。

#### P1-F2 主题与安装

- `system/light/dark` 立即生效并同步 PWA 主题色；未登录保存本地安全值，登录后由服务端偏好回写。
- 安装能力检测中显示 loading；支持时显示安装动作，不支持时显示平台步骤；不展示不可用假按钮。
- 验收：重载无错误主题闪现，白天/夜晚布局不变，网页模式仍可完成全部业务。

### 8.2 P2 记一笔

- **入口/权限**：普通用户默认首页、底部导航；只读取当前租户字典与草稿。
- **原型**：[expense-entry.html](prototypes/expense-entry.html)；对应 R5-R10、R24、R39-R43、R54；受 B2、B3、B5 影响。

#### P2-F1 商品与默认值

- 输入商品名称，最近/高频优先；无结果时可快捷新增。
- 空名称就地报错；疑似重名时提示选择已有商品，具体判重按 B2；选择后带出值但不提交。
- 字典 loading 时表单保留骨架；空字典提供新增；失败提供重试；无权限终止操作。
- 新增成功关闭抽屉并自动选中，取消返回且不丢其他字段；验收覆盖重名、停用和新增回填。

#### P2-F2 金额与字段校验

- 输入分类、单位、单价、数量、实付、支付方式、渠道、时间和备注；规则见 §6.1。
- 单价/数量实时更新计算金额；用户改过实付后不再被覆盖；非法值就地提示。
- 校验无需 loading；字段改变联动金额和候选值；验收覆盖零价、负数、极端值、精度边界和差额。

#### P2-F3 位置选择

- 默认未指定；可选常用地点、请求定位或打开地图选点，选择后明确回填地点摘要。
- 请求中显示 loading并允许取消；失败回到未指定且可重试，不影响其他字段和保存。
- 地图确认后回填；“保存为常用地点”需名称校验，取消不写字典；权限和数据边界见 §6.5。
- 验收覆盖授权成功、拒绝、超时、地图失败、保存常用地点和复用；技术实现等待 B5。

#### P2-F4 保存、连续录入与草稿

- 保存前执行全表单校验；提交中两个保存按钮禁用；成功提供“查看明细”和撤销。
- 保存失败保留输入并重试；会话过期重新登录后恢复当前用户草稿；幂等标识防重复。
- 保存并继续按 §6.1 保留/清空字段；取消离开时若有修改提示保留草稿或放弃。
- 验收覆盖断网、超时已保存、重复点击、跨账号草稿隔离和连续三项录入。

### 8.3 P3 消费报表

- **入口/权限**：普通用户底部导航；只聚合当前租户有效账单。
- **原型**：[reports.html](prototypes/reports.html)；对应 R14-R18、R46-R52、R56、R22。

#### P3-F1 筛选

- 输入时间、分类、商品、支付方式、渠道和地点；应用前校验日期与筛选值。
- 应用期间局部 loading；成功后全部区域同步刷新并显示摘要；清除恢复用户默认范围而非删除偏好。
- 取消关闭抽屉不改变当前条件；筛选无结果显示可清除空态；请求失败保留旧数据并重试。
- 验收：任一区域展示的条件与请求一致，刷新/返回保留当前筛选。

#### P3-F2 维度切换与图表

- 切换趋势、分类、商品、支付方式、渠道、位置、习惯、价格、频次、数据质量时，标题、单位、图形和明细摘要必须同步变化。
- 首次 loading、空数据、局部 error、permission 互斥；切换请求晚返回不得覆盖新维度。
- 图表不只靠颜色，键盘可操作；点击图形或排行项直接进入明细，不能只弹 toast。
- 验收：每个维度至少一个可点击数据点携带正确 `dimension/value/range` 上下文。

### 8.4 P4 账单明细

- **入口/权限**：底部导航或报表下钻；只访问当前租户账单。
- **原型**：[bill-details.html](prototypes/bill-details.html)；对应 R11-R13、R18、R24、R44、R22。

#### P4-F1 查询、有效账单与回收站

- 输入组合筛选；从报表进入时解析并显示来源与条件，非法上下文安全回退。
- “有效账单”和“回收站”是互斥数据集；切换显示对应列表、计数和可用操作，禁止复用错误业务数据。
- 首次/切换 loading，成功无数据分别显示“尚无账单”或“回收站为空”；失败保留筛选并重试。
- 验收：下钻集合与报表一致，回收站不出现有效账单操作，返回报表恢复上下文。

#### P4-F2 查看与编辑

- 点击账单行打开编辑抽屉，包含消费时间、商品、分类、单位、单价、数量、实付、支付方式、渠道、位置和备注。
- 校验与 P2 相同；提交 loading、防重复；取消保留原记录；版本冲突保留输入并提供刷新/重新确认。
- 成功刷新当前列表并使报表失效；验收覆盖每个字段回显、校验、冲突和报表更新。

#### P4-F3 删除、恢复与永久清理

- 有效账单可移入回收站并即时撤销；回收站账单可恢复；永久清理规则等待 B4。
- 删除/恢复期间行级 loading；失败保留当前列表和操作入口；高影响动作二次确认。
- 验收：状态变化后列表、计数和报表一致；原型不得显示未确认的固定天数。

#### P4-F4 导出

- 当前筛选范围可导出；提交时显示进度并防重复；取消未开始任务不生成文件。
- 无数据明确提示；失败可重试；导出完成提供下载且只含当前用户。
- 验收：字段完整、字符编码可在常用表格工具中读取、跨租户负例失败。

### 8.5 P5 我的

- **入口/权限**：普通用户底部导航；只操作当前用户偏好、字典和账号。
- **原型**：[profile-settings.html](prototypes/profile-settings.html)；对应 R9、R10、R13、R19、R40-R45、R54、R22。

#### P5-F1 偏好与主题

- 修改默认支付方式、明细默认范围、报表默认范围和主题；非法或已停用值回退安全默认。
- 修改立即生效并异步保存；保存中显示状态，失败保留会话值并允许重试；恢复默认需确认结果。
- 验收：刷新、重新登录和非法服务端值场景均按规则消费。

#### P5-F2 六类个人字典

- 商品、分类、单位、支付方式、购买渠道、常用地点分别进入对应管理视图，不用同一假列表冒充。
- 每类均覆盖新增、改名、排序、停用、恢复、loading、empty、error、引用保护；商品另覆盖合并，地点受 B5。
- 提交成功刷新所有消费页候选；取消不改数据；验收逐类执行完整维护链路。

#### P5-F3 导出、退出与注销

- 导出按 P4-F4；退出立即使会话失效但不泄漏下一账号草稿。
- 注销前说明影响、建议导出并二次确认；提交中不可重复；失败保留账号正常可用。
- 验收：退出后受保护页不可访问；注销成功会话失效，后台任务和审计可追踪。

### 8.6 P6 系统管理

- **入口/权限**：管理员登录首页；普通用户访问显示 permission error。
- **原型**：[admin-console.html](prototypes/admin-console.html)；对应 R2-R4、R20-R23、R53-R55；用户创建受 B1 阻塞。

#### P6-F1 用户管理

- 查询用户状态和最近活跃；创建、启停、恢复和注销少量用户，认证字段等待 B1。
- 必填与重复校验就地显示；提交 loading、防重复；取消不改账号；高影响操作二次确认并写 R21。
- 空用户提示创建首位用户；失败可重试；普通用户无权限；验收不得在网络模型或页面出现消费字段。

#### P6-F2 默认字典

- 分别维护新用户默认分类、单位、支付方式和购买渠道的新增、排序、停用与恢复。
- 保存中防重复，失败保留编辑；变更只影响此后创建的用户，页面明确显示生效范围。
- 验收：新用户获得副本，存量用户不变，每类 empty/error 可恢复。

#### P6-F3 运行概况

- 展示账号数量、状态、最近活跃、服务健康、备份状态和存储容量，不展示任何消费聚合。
- loading/empty/error/permission 互斥；刷新保留旧值并显示局部 loading；失败可重试。
- 验收：消费字段不在接口模型，服务异常有可定位的状态文字。

#### P6-F4 操作日志

- 按管理员、动作、对象、结果和时间筛选，打开日志详情；只读，不提供删除或修改。
- loading、empty、error、permission 完整；筛选失败保留旧结果；日志不得含密码、令牌、精确坐标或消费内容。
- 验收：创建、启停、恢复、注销和默认字典高影响动作均可追溯。

## 9. 性能、安全、兼容与 DESIGN 约束

- 商品候选限制加载数量并支持搜索；明细服务端分页；报表在服务端按合理范围聚合。
- 避免 N+1、重复聚合、无限缓存和大对象一次性加载；导出与清理采用异步或流式边界。
- 密码采用成熟算法存储；登录与敏感接口限流；退出、停用和改密后旧会话失效。
- 管理员消费数据不可见同时落实到路由、接口模型与数据访问层。
- 支持当前主流 iOS Safari、Android Chrome 和桌面 Chromium；PWA 能力渐进增强。
- 所有手机和平板触摸目标至少 44×44px，键盘焦点可见；正式图标使用统一 SVG/图标库，禁止 emoji 或 Unicode 代替。
- 白天、夜晚、系统跟随、减少动态、横竖屏和虚拟键盘场景均验证；关键视口遵循 DESIGN §8。
- 六页均验证适用的 `ready/loading/error/permission`；报表、明细、字典、管理列表等数据区域另验证 `empty`，不得为没有集合数据的登录表单制造假空态。

## 13. 本轮复核结论

- 审查者指出的“候选默认值伪装成确认、阻塞项降级、原型状态错误、页面闭环不足、触控与 emoji 违规、编号不原子、常用地点验收遗漏、开发阶段提前覆盖”均有当前文件证据，已纳入整改。
- 审查意见中关于 R31 的表述需要校准：当前 R31 是“多商品消费批次”，并非直接支付连接；其确实来源于上游建议项，现已改正来源。
- 全量复核额外发现 R7-R9、R12、R14-R17、R23 也存在独立能力混编，已拆分到 R39-R56；这比原审查列出的三处范围更完整。
- 文档目前仍不应直接进入完整开发计划，原因不是文档框架不完整，而是 B1-B5 尚未获得用户确认。关闭阻塞项后必须再次执行全量复核。
