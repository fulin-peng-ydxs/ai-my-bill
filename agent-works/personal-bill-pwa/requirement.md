# 个人账单 PWA 正式需求文档

## 1. 文档状态与目标

本项目面向中国大陆个人和少量用户，建设一款手机优先、可互联网访问的个人收支账单 PWA。第一期聚焦三条主链路：低负担记录商品级支出、快速记录金额型收入，以及从多维收支报表追溯到原始账目和调整记录。

当前状态为：**支出、收入及退款/报销调整的业务口径均已确认，可作为完整开发计划输入**。

产品目标：

- 常见商品通过最近使用、默认值和连续录入快速保存。
- 收入通过收入名称、付款方、分类、金额和收款方式快速保存，收入名称与付款方均必填。
- 商品、分类、单位、支付方式、购买渠道和常用地点随使用沉淀。
- 报表同时覆盖收支总览、收入维度和既有支出维度，并可下钻到原始账目或调整记录。
- 修改、删除或恢复账单后，明细与报表保持同一口径。
- 一个普通用户对应一个租户，任何访问路径均不得跨租户。
- 以低成本完成试用部署，并保留中国大陆稳定部署、备案和扩容路径。

## 2. 事实来源与确认边界

### 2.1 项目事实

- 当前仓库只有需求、DESIGN 和静态交互原型，没有业务代码、数据库、接口、测试或部署配置。
- 上游闭环事实源为 [requirement-closure.md](requirement-closure.md)。
- 前端设计事实源为 [DESIGN.md](../../DESIGN.md)。
- 六个页面原型位于 [prototypes](prototypes/)，用于验证结构、交互和状态，不替代本文业务规则。

### 2.2 用户已明确确认

- 第一阶段一个普通用户对应一个独立租户，不支持家庭共享账本。
- 商品名称在当前租户的商品字典内唯一；同一商品可以形成多条消费记录。
- 第一阶段采用 PWA，主要服务中国大陆个人和少量用户。
- 主题必须支持白天与夜晚；DESIGN 进一步定义 `system/light/dark` 三种偏好。
- B1-B5 推荐方案已于 2026-08-13 获得用户整体确认，具体决策见 §3。
- 收入采用金额型表单，不使用商品、单位、单价和数量；收入名称、付款方、收入分类、金额、收款方式和收入时间必填。
- 退款与报销优先关联并冲减原支出，不计入收入；第一期不做账户余额和自有账户转账。
- 收入使用靛蓝、支出使用铜橙，并同时使用文字与正负号区分，不使用红绿表达收支。
- B6-B9 推荐方案已于 2026-08-13 获得用户确认：支出分类最多两级且一级必填、二级选填；购买渠道选填并默认“未指定”；人民币和 `Asia/Shanghai` 为第一期固定货币及时区；退款/报销调整按原支出生命周期联动。

### 2.3 非阻塞校准项

下列内容仍可在对应模块前校准，但不得在开发计划、数据模型、接口或原型文案中伪装成用户确认：

| 事项 | 当前候选 | 处理规则 |
| --- | --- | --- |
| 消费批次 | 第一期不引入，只统计消费明细数 | 可维持当前范围；若要统计交易次数需另立需求 |
| 默认带出 | 最近单价、单位、支付方式和渠道 | 只能带出，不能自动提交 |
| 异常阈值 | 采用可解释规则 | 报表开发前确认具体阈值 |

## 4. 用户角色与权限

### 4.1 系统管理员

管理员维护普通用户、面向新用户的默认字典、运行概况和管理员操作日志。管理员默认不能查看、搜索、导出或修改用户收支明细；用户管理返回模型也不得包含商品、收入名称、付款方、金额、位置等账目字段。

### 4.2 普通用户

普通用户只操作自己租户下的支出、收入、退款/报销调整、字典、报表、偏好和导出任务。租户归属必须来自服务端身份上下文，客户端不得提交或切换资产租户标识。

### 4.3 固定入口

普通用户手机端底部导航固定为“记一笔、报表、明细、我的”。管理员登录后进入隔离的系统管理入口；普通用户直接访问管理页面或接口时显示无权限，不伪装成空数据。

## 6. 核心业务规则

### 6.1 填报字段与校验

| 字段 | 必填 | 已确定规则 | 非阻塞校准 |
| --- | --- | --- | --- |
| 消费时间 | 是 | 默认当前时间，不允许明显未来时间；统一按 `Asia/Shanghai` 解释、展示和生成业务日期 | 无 |
| 商品 | 是 | 选择已有或快捷新增；按 B2 规范化后租户内唯一 | 无 |
| 一级分类 | 是 | 选择启用项，已有商品可带出；最多两级结构 | 无 |
| 二级分类 | 否 | 只能选择所属一级分类下的启用项；未选时在报表中显示“未选二级” | 无 |
| 单位 | 是 | 选择启用项，已有商品可带出 | 无 |
| 单位价格 | 是 | `0-99,999,999.9999`，最多 4 位小数，十进制精确计算 | 无 |
| 数量 | 是 | 默认 1，`>0` 且 `≤999,999.999`，最多 3 位小数 | 无 |
| 计算金额 | 系统 | 单价 × 数量后 `ROUND_HALF_UP` 为 2 位，且不超过金额上限 | 无 |
| 实付金额 | 是 | 默认等于计算金额，可修改；`0-999,999,999.99`，最多 2 位小数 | 无 |
| 支付方式 | 是 | 选择启用项，优先用户偏好或最近使用 | 无 |
| 购买渠道 | 否 | 默认“未指定”；空值按 B7 保存和统计，可选择启用字典项 | 无 |
| 购买位置 | 否 | 未指定或当前租户常用地点文本标签；不采集坐标 | 无 |
| 备注 | 否 | 去除首尾空格，长度上限需在接口契约中确定 | 最大长度 |

用户修改实付金额后，单价或数量变化不得静默覆盖；系统显示计算金额与实付金额差额。选择已有商品只带出默认值，不自动保存。保存并继续保留消费时间、支付方式、渠道和位置，清空商品相关字段；复制上一笔更新消费时间并要求用户再次确认。

### 6.2 商品与字典

- 商品唯一键依次执行 Unicode NFKC、去首尾空格、折叠内部连续空白、英文转小写；展示名保留用户输入，不去标点、不自动合并同义词。
- 分类、单位、支付方式、购买渠道和常用地点均支持新增、改名、排序、停用、恢复。
- 停用项不进入新填报默认候选，但历史账单继续显示原快照。
- 被历史账单引用的字典项不得物理删除。
- 商品合并前展示影响数量并二次确认；合并后更新统计归属、保留历史解释并记录去向。
- 系统默认字典只初始化新用户，随后形成个人副本；管理员修改不得覆盖存量用户。

### 6.3 收入字段、字典与校验

| 字段 | 必填 | 已确认规则 |
| --- | --- | --- |
| 收入时间 | 是 | 默认当前时间，不允许明显未来时间 |
| 收入名称 | 是 | 去除首尾空格后非空；不要求唯一；最近使用优先，可重复记录“月度工资”等名称 |
| 付款方 | 是 | 选择已有或快捷新增到个人字典；去除首尾空格后非空 |
| 收入分类 | 是 | 选择启用项；默认候选为工资、奖金、兼职、经营所得、投资收益、利息、礼金与红包、其他收入 |
| 金额 | 是 | `>0` 且 `≤999,999,999.99`，最多 2 位小数，使用十进制精确类型 |
| 收款方式 | 是 | 与支出的支付方式复用同一资金渠道字典，按收入场景显示“收款方式” |
| 备注 | 否 | 去除首尾空格，最大长度在接口契约中确定 |

- 收入不包含商品、单位、单价、数量、购买渠道或购买地点字段，不得用虚拟商品承载收入。
- 收入名称不形成唯一字典；最近使用只用于加速输入。付款方和收入分类形成当前租户个人字典，支持新增、改名、排序、停用和恢复。
- 停用付款方或收入分类不进入新收入候选，历史收入继续显示保存时的名称快照。
- 保存并继续保留收入时间、分类和收款方式，清空收入名称、付款方、金额和备注；复制上一笔收入更新时间并要求再次确认。

### 6.4 退款、报销与非收支资金流

- 消费退款和费用报销均作为支出调整，关联原支出后冲减用户实际承担金额，不计入收入总额。
- 创建入口有两个：有效支出详情中的“记录退款/报销”直接形成已关联调整；收支明细页工具栏的“记录未关联退款/报销”形成待归类调整。不得从收入详情创建调整。
- 支持部分退款/报销和同一原支出的多次调整；已生效调整累计金额不得超过原支出实付金额。
- 完全冲减时原支出显示“已全额退款/报销”，但保留原支出及完整调整轨迹；撤销调整后重新计入净支出。
- 找不到原支出的款项先进入“待归类调整”，用户必须选择关联支出或明确改记为正常收入后才能计入正式报表。
- 原支出移入回收站时，其已关联调整转为“随原支出冻结”，原支出和调整同时退出全部报表；恢复原支出时，未被单独删除或撤销的调整重新生效并重新校验累计金额。
- 原支出存在关联调整时不得单独永久删除。用户必须先撤销/删除关联调整，或在同一二次确认操作中选择“连同关联调整永久删除”；到期清理遵循同一原子规则，不产生孤立调整。
- 调整自身软删除或撤销后立即停止冲减；恢复调整前重新校验原支出有效状态和累计上限，不满足时保持冻结并提示处理。
- 自有资金渠道之间的转账不属于收入或支出；第一期不记录转账，也不计算微信、支付宝、银行卡或现金余额。

### 6.5 明细、删除、导出与注销

- 明细先按全部/支出/收入/退款与报销筛选，再按对应业务字段组合查询；默认按业务时间、创建时间倒序稳定排列。
- 支出与收入编辑分别复用各自填报字段和校验；若记录版本已变化，保留用户输入并提示刷新或重新确认。
- 软删除账单立即退出有效报表并提供撤销；回收站保留 30 天，期间可恢复或二次确认后永久删除，到期由可审计后台任务清理。
- CSV 导出必须包含账目类型、调整类型和关联账目标识；支出导出消费字段，收入导出收入时间、名称、付款方、分类、金额和收款方式，且只包含当前用户。
- 注销前建议导出并二次确认；注销使会话失效，数据删除或受控保留需满足正式运营隐私政策。

### 6.6 报表统一口径

- 支出金额统一使用实付金额，收入金额使用收入金额；各自使用业务发生时间，只统计未删除且已正式归类的账目。
- 每条账单是一条商品消费明细，数量指标称“消费明细数”，不得称“交易笔数”。
- 同一商品不同单位的数量和单价分别统计，不能直接相加；金额可汇总。
- “填写单价”和“实付金额 ÷ 数量”的“实际单位成本”必须分别命名。
- 同比无可比期、环比前期为零或数据不完整时显示不可计算及原因。
- 全局筛选支持时间和账目类型；支出范围增加支出分类、商品、支付方式、购买渠道和常用地点，收入范围增加收入分类、付款方、收入名称和收款方式；所有区域显示并消费同一摘要。
- 点击时间点、分类、商品、支付方式、渠道、地点或异常线索进入明细并携带可序列化上下文；返回恢复筛选、维度和滚动位置。
- 总收入只汇总有效正常收入；原始支出汇总有效支出的实付金额；退款冲减汇总有效调整；净支出＝原始支出－退款冲减；结余＝总收入－净支出。
- 收入按时间、收入分类、收款方式、付款方、收入名称和频次分析；所有维度均可下钻到组成指标的收入明细。
- 收支统一筛选必须包含账目类型；支出专属筛选不得错误作用于收入，收入专属筛选不得错误作用于支出。

### 6.7 地点标签与后期精准位置

- 第一期购买位置只保存“未指定”或当前租户的常用地点文本标签，不请求定位权限，不存储坐标，不调用地图服务。
- 地点标签属于当前租户业务数据；管理员不可见，历史引用保护与其他个人字典一致。
- 精准定位、地图选点和逆地理编码属于后期增强 R57；第一期正式页面不得展示不可用的定位或地图占位控件。

R57 只有同时满足以下条件才可立项：

- 文本地点标签不能满足真实分析需求，并有使用数据或访谈证据。
- 已确定中国大陆访问可用、成本可控的地图服务及配额告警方案。
- 已完成定位用途、授权时机、保留期限、导出和删除的隐私说明。
- 精准位置的分析价值高于 SDK、合规、故障降级和数据保护成本。

进入 R57 技术方案时应优先评估届时可用的高德地图 JavaScript API 和 GCJ-02 坐标；开发前必须重新核验服务条款、价格与浏览器兼容性，不把当前候选供应商固化为长期契约。定位权限只能由用户主动动作触发，不得在页面加载时自动请求。

### 6.8 四态与动作反馈

- 页面及独立数据区采用互斥的 `ready/loading/empty/error`；无权限属于 error 变体，不是假空态。
- 首次加载不显示空态；已有数据刷新保留旧值并显示局部 loading。
- 空态解释为什么为空并提供下一步；普通错误提供重试；无权限不提供无意义重试。
- 保存、删除、导出等异步动作显示 loading、防重复触发；动作失败保留用户输入。
- 原型统一用查询参数 `?state=loading|empty|error|permission` 验证状态承载，`ready` 为默认；登录等没有集合数据的页面不强制制造业务空态，`empty` 只验收其独立数据区域。

## 7. 数据与接口边界

| 实体 | 核心属性 | 关键约束 |
| --- | --- | --- |
| 用户 | 用户名、密码摘要、临时密码状态、账号状态、最近活跃 | 用户名全局唯一；普通用户唯一归属一个租户 |
| 租户 | 标识、状态 | 第一阶段一用户一租户 |
| 商品 | 稳定 ID、展示名、规范化唯一键、分类、默认单位、最近值、状态 | “租户 + 规范化唯一键”唯一 |
| 支出分类/单位/资金渠道/购买渠道 | 稳定 ID、名称、排序、状态 | 租户内维护，资金渠道按场景显示为支付方式或收款方式，历史引用保护 |
| 常用地点 | 稳定 ID、文本名称、排序、状态 | 租户内维护；第一期不含坐标或地图服务字段 |
| 收入分类 | 稳定 ID、名称、排序、状态 | 租户内维护；默认字典只初始化新用户 |
| 付款方 | 稳定 ID、展示名、排序、状态 | 租户内维护；保存收入时保留名称快照 |
| 账目 | 类型、业务时间、支出或收入字段、名称快照、删除状态、删除时间、版本 | 类型决定字段集合；租户不可由客户端指定；回收站 30 天 |
| 支出调整 | 调整类型、可空原支出、金额、业务时间、状态、备注 | 状态含待归类、已生效、随原支出冻结、已撤销、已删除；有效累计金额不超过原实付，待归类和冻结不进入正式报表 |
| 用户偏好 | key、合法值、更新时间 | 服务端为登录态权威，本地仅安全回退 |
| 管理操作日志 | 管理员、动作、对象、结果、时间 | 不记录凭据、坐标和用户账目内容 |

- 所有业务接口从认证上下文确定用户和租户，不接受任意租户参数。
- 字典引用、筛选和偏好传递稳定 ID，展示名称只用于界面与历史快照；筛选占位等内部哨兵值使用独立命名空间，不得与字典 ID 或用户可维护名称混用。
- 写接口提供字段校验、版本冲突和幂等结果；账单与最近使用信息保持一致。
- 修改、删除、恢复和商品合并后使相关报表缓存失效。
- 金额和数量使用十进制精确类型并按 B3 固化 scale；禁止浮点近似计算。
- 导出采用受控任务或流式响应，避免大数据一次性加载。
- 永久清理与注销采用可审计后台任务，不由前端直接批量物理删除。
- R57 启用后，常用地点扩展用户展示名、GCJ-02 坐标、地址摘要、来源类型、地图服务商和解析版本；账单保存位置快照与字典引用，字典改名不得改变历史快照。
- 精确坐标属于敏感业务数据，必须租户隔离、受控导出和删除；管理端、普通日志、分析埋点和错误上报均不得记录精确坐标。

## 8. 页面与逐功能交互闭环

以下六页均为新增页面。每个功能点均说明输入、校验、动作、状态、权限、刷新联动和验收；共同的视觉、四态、弹层、触控和响应式规则以 DESIGN 为事实源。

### 8.1 P1 登录与安装

- **入口/权限**：未登录访问应用或会话失效回跳；登录成功后按角色进入“记一笔”或系统管理。
- **原型**：[login.html](prototypes/login.html)；对应 R1、R2、R22、R54；认证规则按 B1。

#### P1-F1 登录

- 输入用户名与密码；管理员创建用户后一次性展示 16 位临时密码，24 小时内首次登录必须设置 15-64 位正式密码。
- 两字段为空时就地提示；提交期间按钮 loading 且禁止重复请求；取消不适用。
- 成功按角色跳转；凭据错误、账号停用、网络失败和系统失败在表单区反馈，不泄露账号是否存在。
- 会话失效返回本页；重试不清空账号字段；未登录用户可用，已登录用户进入对应首页。
- 忘记密码不依赖手机号或邮箱自助找回；用户联系管理员重置，重置后旧会话全部失效，新临时密码仍仅展示一次且 24 小时有效。
- 验收：键盘回车可提交，失败可恢复，重复点击只产生一次请求。

#### P1-F2 主题与安装

- `system/light/dark` 立即生效并同步 PWA 主题色；未登录保存本地安全值，登录后由服务端偏好回写。
- 安装能力检测中显示 loading；支持时显示安装动作，不支持时显示平台步骤；不展示不可用假按钮。
- 验收：重载无错误主题闪现，白天/夜晚布局不变，网页模式仍可完成全部业务。

### 8.2 P2 记一笔

- **入口/权限**：普通用户默认首页、底部导航；只读取当前租户字典与草稿。
- **原型**：[expense-entry.html](prototypes/expense-entry.html)；对应 R5-R10、R24、R39-R43、R54、R58-R60、R67、R70、R71；规则按 B2、B3、B5 和 §6.3。

#### P2-F1 商品与默认值

- 输入商品名称，最近/高频优先；无结果时可快捷新增。
- 空名称就地报错；按 B2 规范化后重名时提示选择已有商品；选择后带出值但不提交。
- 字典 loading 时表单保留骨架；空字典提供新增；失败提供重试；无权限终止操作。
- 新增成功关闭抽屉并自动选中，取消返回且不丢其他字段；验收覆盖重名、停用和新增回填。

#### P2-F2 金额与字段校验

- 输入分类、单位、单价、数量、实付、支付方式、渠道、时间和备注；规则见 §6.1。
- 单价/数量实时更新计算金额；用户改过实付后不再被覆盖；非法值就地提示。
- 校验无需 loading；字段改变联动金额和候选值；验收覆盖零价、负数、极端值、精度边界和差额。

#### P2-F3 地点标签选择

- 默认未指定；可选择当前租户已启用的常用地点文本标签，或进入管理入口新增标签。
- 标签列表 loading 时不阻断其他字段；失败保留“未指定”和重试入口；取消新增不写字典、不改变当前选择。
- 新增名称按字典通用规则校验，成功后回填并立即可复用；第一期页面不得请求定位权限或展示地图占位控件。
- 验收覆盖未指定、标签复用、新增、重名、停用、加载失败和跨租户负例。

#### P2-F4 保存、连续录入与草稿

- 保存前执行全表单校验；提交中两个保存按钮禁用；成功提供“查看明细”和撤销。
- 保存失败保留输入并重试；会话过期重新登录后恢复当前用户草稿；幂等标识防重复。
- 保存并继续按 §6.1 保留/清空字段；取消离开时若有修改提示保留草稿或放弃。
- 验收覆盖断网、超时已保存、重复点击、跨账号草稿隔离和连续三项录入。

#### P2-F5 收入填报与类型切换

- 页面顶部在“支出/收入”间互斥切换，默认恢复当前用户最近使用类型；切换不提交、不清除另一类型草稿，两个类型的校验和草稿键隔离。
- 收入表单输入收入时间、收入名称、付款方、收入分类、金额、收款方式和备注；除备注外均必填，收入名称与付款方去除首尾空格后仍须非空，金额按 §6.3 校验。
- 付款方无匹配时可快捷新增，保存收入成功后加入个人字典并回填；重名、停用项、字典加载失败和跨租户访问按通用字典规则处理。
- 提交 loading、防重复、失败保留输入、会话恢复和保存并继续规则与支出一致；收入名称不执行唯一约束，允许重复记录。
- 验收覆盖空收入名称、空付款方、非法金额、新付款方回填、类型往返草稿不丢、最近类型恢复及收入保存后报表和明细同步。

#### P2 后期增强：R57 精准位置交互闭环

1. 用户主动选择“获取当前位置”或“地图选点”，系统在首次请求前说明用途。
2. 用户拒绝、撤回或系统定位不可用时，保留全部表单内容，并允许继续使用文本地点标签或“未指定”。
3. 定位或选点成功后展示可确认的地址摘要，不自动保存账单。
4. 用户可修改常用地点展示名，并明确选择是否保存为字典项；取消不得写入字典。
5. 保存账单后记录位置快照和字典引用；编辑、导出、删除和注销沿用账单权限与生命周期。
6. 超时、精度不足、SDK 加载失败、配额耗尽或逆地理编码失败均需说明原因并可降级；重复重试节流，不展示假地图或伪造地址。

该闭环只约束未来 R57，不进入第一期 P2 页面和验收。

### 8.3 P3 收支报表

- **入口/权限**：普通用户底部导航；只聚合当前租户有效且已正式归类的账目和调整。
- **原型**：[reports.html](prototypes/reports.html)；对应 R14-R18、R46-R52、R56、R22、R63、R65、R66。

#### P3-F1 筛选

- 先选全部/支出/收入，再输入时间和对应类型的专属条件；应用前校验日期与筛选值，不显示或发送不适用于当前类型的条件。
- “全部”只显示时间与通用资金渠道；“支出”增加一级/二级分类、商品、购买渠道和地点；“收入”增加收入分类、付款方和收入名称。切换范围时清除不适用条件并更新筛选摘要。
- 资金渠道筛选提交稳定字典 ID；“全部渠道”等不限条件使用不属于字典 ID 的内部哨兵值。若真实渠道名称与占位文案相同，选项和筛选摘要必须差异化显示，不能产生相同请求值或不可理解的上下文。
- 应用期间局部 loading；成功后全部区域同步刷新并显示摘要；清除恢复用户默认范围而非删除偏好。
- 取消关闭抽屉不改变当前条件；筛选无结果显示可清除空态；请求失败保留旧数据并重试。
- 验收：任一区域展示的条件与请求一致，刷新/返回保留当前筛选。

#### P3-F2 维度切换与图表

- 全部范围展示收入、原始支出、退款/报销冲减、净支出与结余；支出范围提供趋势、分类、商品、支付方式、渠道、位置、习惯、价格、频次和数据质量；收入范围提供趋势、收入分类、付款方、收入名称、收款方式和频次。
- 切换范围或维度时，标题、单位、图形、金额色彩和明细摘要必须同步变化；收入用靛蓝、支出用铜橙，并始终辅以文字和正负号。
- 首次 loading、空数据、局部 error、permission 互斥；切换请求晚返回不得覆盖新维度。
- 图表不只靠颜色，键盘可操作；点击图形或排行项直接进入明细，不能只弹 toast。
- 下钻上下文至少包含 `scope`、`dimension`、业务维度值 `value`、`range` 和已应用筛选；不得用指标金额代替维度值。返回报表恢复范围、维度、筛选和滚动位置。
- 验收：每个维度至少一个可点击数据点携带正确上下文；例如“分类=餐饮、金额=528”必须传 `value=餐饮`，不能传 `value=528`。

### 8.4 P4 收支明细

- **入口/权限**：底部导航或报表下钻；只访问当前租户账单。
- **原型**：[bill-details.html](prototypes/bill-details.html)；对应 R11-R13、R18、R24、R44、R22、R61-R64。

#### P4-F1 查询、有效账单与回收站

- 先按全部/支出/收入/退款与报销选择账目类型，再输入该类型的组合筛选；从报表进入时解析并显示来源与条件，非法上下文安全回退。
- “有效账单”和“回收站”是互斥数据集；切换显示对应列表、计数和可用操作，禁止复用错误业务数据。
- 首次/切换 loading，成功无数据分别显示“尚无账单”或“回收站为空”；失败保留筛选并重试。
- 验收：下钻集合与报表一致，回收站不出现有效账单操作，返回报表恢复上下文。

#### P4-F2 查看与编辑

- 点击支出打开支出编辑抽屉，包含消费时间、商品、分类、单位、单价、数量、实付、支付方式、渠道、位置和备注；点击收入打开收入编辑抽屉，包含 §6.3 全部字段。
- 各自复用 P2 对应校验；提交 loading、防重复；取消保留原记录；版本冲突保留输入并提供刷新/重新确认。
- 成功刷新当前列表并使报表失效；验收覆盖每个字段回显、校验、冲突和报表更新。

#### P4-F3 删除、恢复与永久清理

- 有效账单可移入回收站并即时撤销；回收站账单在删除后 30 天内可恢复，也可经二次确认立即永久删除。
- 删除/恢复期间行级 loading；失败保留当前列表和操作入口；高影响动作二次确认。
- 验收：状态变化后列表、剩余天数、计数和报表一致；到期后台清理幂等且留审计结果。

#### P4-F4 导出

- 当前筛选范围可导出；提交时显示进度并防重复；取消未开始任务不生成文件。
- 无数据明确提示；失败可重试；导出完成提供下载且只含当前用户。
- 验收：字段完整、字符编码可在常用表格工具中读取、跨租户负例失败。

#### P4-F5 退款与报销调整

- 从有效支出进入“记录退款/报销”，选择调整类型、金额、时间和备注；原支出自动锁定，不允许关联收入。
- 明细页工具栏提供“记录未关联退款/报销”，输入调整类型、金额、时间、来源摘要和备注后保存为待归类调整；保存成功后进入退款/报销类型列表。
- 金额必须大于 0，且与该支出其他有效调整累计后不超过原实付；提交前显示调整后净支出，提交 loading 且防重复。
- 找不到原支出时可暂存“待归类调整”，但必须醒目标记且不进入正式报表；用户可继续关联支出或明确改记正常收入。
- 调整可查看、撤销和软删除；变化后原支出状态、明细和全部相关报表同步刷新并保留审计轨迹。原支出删除/恢复/永久清理按 B9 联动。
- 验收覆盖部分、多次、恰好全额、超额拒绝、撤销、独立入口待归类、关联、改记收入、原支出删除后冻结、恢复后重生效、关联存在时阻止单独永久删除、联动永久删除和并发调整。

### 8.5 P5 我的

- **入口/权限**：普通用户底部导航；只操作当前用户偏好、字典和账号。
- **原型**：[profile-settings.html](prototypes/profile-settings.html)；对应 R9、R10、R13、R19、R40-R45、R54、R22。

#### P5-F1 偏好与主题

- 修改默认支付方式、明细默认范围、报表默认范围和主题；非法或已停用值回退安全默认。
- 修改立即生效并异步保存；保存中显示状态，失败保留会话值并允许重试；恢复默认需确认结果。
- 验收：刷新、重新登录和非法服务端值场景均按规则消费。

#### P5-F2 八类个人字典

- 商品、支出分类、单位、资金渠道、购买渠道、常用地点、收入分类、付款方分别进入对应管理视图，不用同一假列表冒充。
- 资金渠道改名只更新展示名称，不改变偏好、填报或历史引用使用的稳定 ID；渠道名称与“管理资金渠道”等操作文案相同时，正式渠道选项与操作入口必须通过可见文案或无障碍名称明确区分。
- 每类均覆盖新增、改名、排序、停用、恢复、loading、empty、error、引用保护；商品另覆盖合并，地点第一期只维护文本标签。收入名称仅提供最近使用，不建立唯一字典。
- 提交成功刷新所有收支页面候选；取消不改数据；验收逐类执行完整维护链路。

#### P5-F3 导出、退出与注销

- 导出按 P4-F4；退出立即使会话失效但不泄漏下一账号草稿。
- 注销前说明影响、建议导出并二次确认；提交中不可重复；失败保留账号正常可用。
- 验收：退出后受保护页不可访问；注销成功会话失效，后台任务和审计可追踪。

### 8.6 P6 系统管理

- **入口/权限**：管理员登录首页；普通用户访问显示 permission error。
- **原型**：[admin-console.html](prototypes/admin-console.html)；对应 R2-R4、R20-R23、R53-R55；用户创建按 B1。

#### P6-F1 用户管理

- 查询用户状态和最近活跃；以全局唯一用户名创建、启停、恢复、重置密码和注销少量用户；临时密码只展示一次。
- 必填与重复校验就地显示；提交 loading、防重复；取消不改账号；高影响操作二次确认并写 R21。
- 空用户提示创建首位用户；失败可重试；普通用户无权限；验收不得在网络模型或页面出现用户账目字段。

#### P6-F2 默认字典

- 分别维护新用户默认支出分类、收入分类、单位、资金渠道和购买渠道的新增、排序、停用与恢复；付款方属于用户私有数据，不提供管理员默认值。
- 保存中防重复，失败保留编辑；变更只影响此后创建的用户，页面明确显示生效范围。
- 验收：新用户获得副本，存量用户不变，每类 empty/error 可恢复。

#### P6-F3 运行概况

- 展示账号数量、状态、最近活跃、服务健康、备份状态和存储容量，不展示任何用户账目聚合。
- loading/empty/error/permission 互斥；刷新保留旧值并显示局部 loading；失败可重试。
- 验收：用户账目字段不在接口模型，服务异常有可定位的状态文字。

#### P6-F4 操作日志

- 按管理员、动作、对象、结果和时间筛选，打开日志详情；只读，不提供删除或修改。
- loading、empty、error、permission 完整；筛选失败保留旧结果；日志不得含密码、令牌、精确坐标或用户账目内容。
- 验收：创建、启停、恢复、注销和默认字典高影响动作均可追溯。

## 9. 性能、安全、兼容与 DESIGN 约束

- 商品候选限制加载数量并支持搜索；明细服务端分页；报表在服务端按合理范围聚合。
- 避免 N+1、重复聚合、无限缓存和大对象一次性加载；导出与清理采用异步或流式边界。
- R57 第三方地图调用必须设置超时、配额告警、熔断和错误归类，并避免重复逆地理编码。
- 密码采用成熟算法存储；登录与敏感接口限流；退出、停用和改密后旧会话失效。
- 管理员用户账目不可见同时落实到路由、接口模型与数据访问层。
- 支持当前主流 iOS Safari、Android Chrome 和桌面 Chromium；PWA 能力渐进增强。
- 所有手机和平板触摸目标至少 44×44px，键盘焦点可见；正式图标使用统一 SVG/图标库，禁止 emoji 或 Unicode 代替。
- 白天、夜晚、系统跟随、减少动态、横竖屏和虚拟键盘场景均验证；关键视口遵循 DESIGN §8。
- 六页均验证适用的 `ready/loading/error/permission`；报表、明细、字典、管理列表等数据区域另验证 `empty`，不得为没有集合数据的登录表单制造假空态。

## 13. 本轮复核结论

- 审查者指出的“候选默认值伪装成确认、阻塞项降级、原型状态错误、页面闭环不足、触控与 emoji 违规、编号不原子、常用地点验收遗漏、开发阶段提前覆盖”均有当前文件证据，已纳入整改。
- 审查意见中关于 R31 的表述需要校准：当前 R31 是“多商品消费批次”，并非直接支付连接；其确实来源于上游建议项，现已改正来源。
